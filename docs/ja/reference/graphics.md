# 端末内の画像表示

[English](../../en/reference/graphics.md)

Kitty graphicsを使うと、文字と同じ端末画面へ静止画やアニメーションを表示できます。
boxrig coreが画像データと配置を解釈し、boxrig UIが文字と重ねて描画します。
以下は、`boxrig_term`で`boxrig_emitter`の`kitty-image-static`を表示した例です。

![Kitty graphicsによる端末内の画像表示](../../../images/kitty-image-static.png)

同じ表示を試す手順は[boxrig_emitter](../boxrig_emitter.md#ケースを選ぶ)を参照してください。
この文書では、画像を送る側の指定と対応範囲を説明します。
外部ファイルなどの許可と非同期処理は[ホスト連携](../host-integration.md)、画面に固定する背景画像は[背景の設定](../background.md)を参照してください。

## 対応する画像プロトコル

[Kitty graphics protocol](https://sw.kovidgoyal.net/kitty/graphics-protocol/)の`APC G header ; payload ST`を解釈します。
静止画、分割転送、外部データ、通常配置、相対配置、Unicode placeholder、アニメーションに対応します。
sixelとiTerm2画像には対応していません。

文字の背景、画像、文字、カーソルは重ねて描画します。
画像の`z`が負なら文字の下、0以上なら文字の上です。
十分小さい負の`z`はセル背景の下になります。
カーソルとIMEの未確定文字はその上に描画します。

## 画像の登録と配置

| 操作 | 指定 | 結果・条件 |
| --- | --- | --- |
| 登録 | `a=t` | 画像を保持する。省略時も同じ |
| 登録と配置 | `a=T` | 受信完了時のカーソル位置へ配置 |
| 問い合わせ | `a=q` | 転送の妥当性を確認し、画像を保持しない |
| 配置 | `a=p` | 登録済みの画像を参照 |
| 削除 | `a=d` | 次節の条件で配置・画像を削除 |

非0の画像IDを再登録すると、復号に成功した時点で旧画像と配置を置き換えます。
IDが0または省略の場合は複数の匿名画像を保持できますが、後の`a=p`から参照できません。
画像番号で登録すると新しいIDを割り当て、同じ番号の問い合わせと削除は最後に登録した生存画像へ適用します。
wire上の32-bit IDとAPIで得る64-bit資源識別子は異なります。

配置は、元画像の切り出し`x/y/w/h`、セル内のピクセルずれ`X/Y`、表示する列数・行数`c/r`、重なり順`z`、配置IDとカーソル移動指定を扱います。
ホストが`boxrig_terminal_set_cell_pixel_geometry()`で正のセル寸法を設定していない場合、配置は`ENOTSUP`です。
フォント変更後は、論理的な配置条件を保ってピクセル位置を解決し直します。

`U=1`の仮想配置では、U+10EEEEのplaceholderの前景色から画像ID、下線色から配置ID、仕様で定めた結合文字から行列と上位IDを読み取ります。
`P/Q/H/V`は親配置からの相対配置です。
親がない場合は`ENOPARENT`、循環は`ECYCLE`、16段を超える親子関係は`ETOODEEP`となります。

## 更新と削除

削除の小文字指定は配置を消し、大文字指定は参照されなくなった画像データも解放します。

| `d`の値 | 対象 |
| --- | --- |
| `a/A` | 表示領域と交差する配置 |
| `i/I`、`n/N` | 画像ID、画像番号。`p`を加えると配置IDも指定 |
| `r/R` | `x`から`y`までの画像ID |
| `c/C` | 現在のカーソルセルと交差する配置 |
| `p/P`、`q/Q` | 1基点の`x/y`セルと交差する配置。`q/Q`は`z`も一致するもの |
| `x/X`、`y/Y`、`z/Z` | 指定した列、行、重なり順 |

### アニメーション

| 操作 | 主な指定と条件 |
| --- | --- |
| フレーム追加・編集 `a=f` | `r=0`または省略で追加、1以上で編集。最初の画像がフレーム1 |
| 合成 `a=c` | `r`のフレームから`c`のフレームへ矩形を合成。`C=0`でsource-over、1で置換 |
| 再生制御 `a=a` | `c`で表示フレーム、`r/z`で表示時間、`s`で状態、`v`で繰り返しを指定 |
| フレーム削除 `a=d,d=f/F` | `r`で対象を指定。0は先頭、末尾を超えた値は末尾 |

各フレームのcanvas寸法は最初の画像と同じです。
追加時の`z`の既定値は40 ms、負値は待ち時間なしです。
編集時の0は既存時間を保ちます。
`X=0`は重ね合わせ、1は置換です。
合成の矩形が画像外へ出る場合や、同一資源の領域が重なる場合は拒否します。

再生の`s=1`は停止、2は読み込み中、3はループです。
`v=1`は無限、1より大きければ`v-1`周、0は既存値を保ちます。
待ち時間が正のフレームがないループは回しません。
削除後は番号を詰め、表示中のフレームを消した場合は次、なければ前を選びます。
最後のフレームに対する小文字削除は画像を残し、大文字削除は画像自体を消します。

再生には単調増加時計が必要です。
長く停止した後は途中の全フレームを描画せず、経過時間に対応する状態へ進めます。
時計と再描画の接続は[点滅](../blinking.md)と共通です。

## 転送方法とホストの許可

| `t` | 転送方法 | 条件 |
| --- | --- | --- |
| `d` | Base64で直接転送 | 既定。`m=1`で継続し、最後は`m=0` |
| `f` | 通常ファイル | ホストの読み取り許可が必要 |
| `t` | 一時ファイル | ホストが読み取りと削除を担当 |
| `s` | 共有メモリ | POSIX共有メモリ、Windowsの名前付きmappingなどをホストが解決 |

Base64は空白、URL-safe文字、不正なpaddingを認めません。
直接転送の継続断片は4文字単位で、続くヘッダーには`m/q`だけを指定します。
フレーム転送では`a=f`も使えます。
異なるコマンドを挟むと転送を中止します。
`a=T`の位置は最終STを受け取った時点で決まります。

外部名もBase64で送り、NULを含めません。
`O/S`は読み取り範囲を指定し、`S=0`は容量上限までの終端読み取りです。
外部転送に分割指定`m=1`は使えません。
coreはファイルや共有メモリを直接開かず、要求をホストへ渡します。

付属端末では外部転送を既定で拒否し、`BOXRIG_ALLOW_GRAPHICS_EXTERNAL=1`で許可します。
一時ファイルは、許可する一時ディレクトリ配下で名前に`tty-graphics-protocol`を含むものだけが対象です。
読み取りの成否にかかわらず削除を試みます。
組み込みアプリケーションは、自分の用途に合う許可と完了処理を実装してください。

## 形式・寸法・容量の制限

形式は`f=24`のRGB、`f=32`のRGBA、`f=100`のPNGです。
`o=z`はzlib形式の圧縮で、raw deflateやgzipを自動判別しません。
内部ではstraight alphaのRGBA8、sRGBとして保持します。
PNGのパレット、グレースケール、16-bit、interlace、tRNSを解釈しますが、APNGの追加フレームをアニメーションとして再生しません。

| 制限・設定 | 既定値または固定上限 |
| --- | --- |
| ヘッダー、1列のpayload | 1,024バイト、4,096バイト |
| 画像の幅・高さ | それぞれ最大1,000,000ピクセル。容量制限も適用 |
| `graphics_storage_capacity` | 128 MiB |
| `graphics_decode_capacity` | 192 MiB |
| `graphics_image_capacity` | 4,096画像 |
| `graphics_placement_capacity` | 8,192配置 |
| `graphics_transport_name_capacity` | 4 KiB |
| `graphics_animation_storage_capacity` | 640 MiB |
| `graphics_frame_capacity` | 16,384フレーム |

上限分のメモリを生成時に確保するわけではありません。
必要に応じて確保し、保持量に応じて使われていない画像などを解放します。
新しい転送が失敗した場合は、それまでの有効な画像を保持します。

7項目を全て0にすると画像機能を無効にします。
基本4項目は一部だけ0にできません。
外部名の容量だけを0にすると外部転送を、アニメーションの2項目を共に0にするとアニメーションを無効にできます。
正確な設定条件は[terminal.h](../../../include/boxrig/terminal.h)を参照してください。

## 未対応の指定と応答

応答は`APC G`に画像IDなどと`OK`またはエラー名を続けます。
主なエラーは`EINVAL`、`EBADZLIB`、`EBADPNG`、`ENOENT`、`ENOSPC`、`ENOTSUP`、`EACCES`、`EIO`です。
`q=0`は全応答、1はエラーだけ、2は無応答です。
画像IDも番号もなければ応答しません。

応答は最大160バイトを一度に追加します。
送信キューが満杯なら最終STで`WOULD_BLOCK`となり、再試行しても登録と応答を二重に行いません。

OS付属ConPTYでは、画像列がboxrigへ届く前のVT解釈・再出力で失われる場合があります。
[上流の議論](https://github.com/microsoft/terminal/issues/1985)と[環境別対応](./platform-support.md)を参照してください。
coreで解析できることと、子プロセスから画像列がそのまま届くことは別の条件です。
