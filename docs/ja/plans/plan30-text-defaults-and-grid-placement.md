# plan30 端末の文字配置の既定値とセル領域の余白

2026年11月23日作成。調査の基準は、同日にリモートと照合したboxrigの`origin/develop`（`0fb7d5f`）です。利用側はelder-termsの`254bddc8`を参照しました。[boxrigの基準コミット](https://github.com/kekyo/boxrig/commit/0fb7d5fcccd7490b390e55e2c6ac1a604683c1d4)・[elder-termsの端末生成処理](https://github.com/kekyo/elder-terms/blob/254bddc8816b38f2e74a8baa22c971492053fcf1/elder-terms-terminal/src/terminal-runtime.cpp#L1233-L1261)

画面の行と桁を指定して文字を配置する端末アプリ（TUI）向けに、文字の並び順と絵文字の幅の既定値を合わせます。もう一つの変更はセル領域の配置です。アプリから四辺の余白を指定し、ウインドウの高さをセルで割った端数を上か下に置けるようにします。設定画面とズーム時のウインドウ操作は、elder-termsの`docs/ja/plans/plan29-terminal-layout-and-file-drops.md`で扱います。

## 30.1 文字を端末のセル順に表示する

現在のライブラリの既定値は`BOXRIG_TEXT_DIRECTION_AUTO`です。アラビア文字やヘブライ文字を含む行では、双方向文字の規則に従って表示順を決めます。付属端末`boxrig_term`とelder-termsは、文脈に応じて字形を整えながら端末のセル順を保つ`BOXRIG_TEXT_DIRECTION_LOGICAL`を明示しています。[文字配置の説明](../fonts-and-layout.md)・[公開APIの各方針](../../../include/boxrig/ui/text_layout.h#L24-L34)・[GTK3ウィジェットの初期値](../../../src/gtk3/terminal_widget.c#L2264)

設定を省略した出力に英字と右から左に書く文字を混在させ、描画、クリック、選択してコピーした文字列を照合します。現行版で差を確認してから、既定値を`LOGICAL`に変更します。対象はGTK3・GTK4、X11・Wayland・Win32のコンポーネントと、単独で生成できる描画器です。列挙値はそのまま使い、`AUTO`や段落方向を明示した場合の表示も確かめます。[各出力に共通の試験](../../../tests/frontend_component_fixture.c)・[文字の並び順と表示位置の試験](../../../tests/test_ui_platform_fixture.c)

完了条件は、設定を省略したGTK3ドライバーで混在行の描画と操作が同じセルを指し、各出力の試験でも同じ既定値になることです。描画方式の切り替えとウィジェットの再生成を経た画面でも確かめ、この変更だけをコミットします。

## 30.2 絵文字表示指定子を受けたときの文字幅を揃える

絵文字表示指定子VS16（U+FE0F）は、直前の文字に絵文字としての表示を指定します。boxrig単体の既定値は`BOXRIG_EMOJI_VARIATION_WIDTH_WIDE`です。前段の表示順とは別に、端末生成時の既定値を、付属端末とelder-termsが使う`BOXRIG_EMOJI_VARIATION_WIDTH_PRESERVE`に変更します。[端末設定の既定値](../../../src/core/terminal.c#L176)・[文字幅の仕様](../fonts-and-layout.md)

試験で観測するのは、1列のハートとVS16を別々に送ったときの後続文字とカーソルの桁です。変更前の失敗を確認してから既定値を切り替えます。行末の折り返し、もとから2列の絵文字、国旗、キーキャップも同じドライバーで表示します。[既存の端末コア試験](../../../tests/test_terminal.c)

完了条件は、設定を省略するとハートが1列に収まり、後続文字が隣のセルに表示されることです。`WIDE`を明示すれば2列へ広がることも検証し、文字方向とは独立してコミットします。

## 30.3 四辺のパディングとセル領域の原点を決める

パディングは端末の表示面の縁と文字セルの間に常に取る幅です。セル領域の原点は、先頭行の左端を描く位置です。現在のレイアウト結果は、セル領域全体の幅・高さと右辺・下辺の余りを返します。座標からセルを求める処理は、表示面の左上をそのまま原点として使っています。[レイアウト結果の公開定義](../../../include/boxrig/ui/view.h#L251-L267)・[端数の計算](../../../src/ui/view.c#L897-L906)・[座標からセルを求める処理](../../../src/ui/view.c#L3959-L3970)

GTK3のドライバーから四辺共通のパディングを指定できるようにします。単位は表示倍率に依存しない論理ピクセル（DIP）、既定値は0です。共通ビューで上下・左右のパディングを引いた領域に入る行数と桁数を求めます。ホストに要求する寸法は、その行数・桁数に必要な幅と高さに各辺のパディングを一度ずつ足した値です。スクロールバーはセル領域の外に置き、パディングにも端末の背景色・背景画像・透過を反映します。

最初の試験は、パディングを指定した画面で先頭セルの描画とクリック位置を照合するものです。GTK3のCairoとOpenGLで同じ原点を使い、文字、カーソル、画像、選択範囲、リンクを配置します。入力メソッド（IME）の変換中の文字と候補の位置、ポインター座標から行・桁への変換にもこの原点を使います。[共通ビューの試験](../../../tests/test_ui.c)・[GTK3の表示・操作試験](../../../tests/gtk3/test_gtk3_widget.c)・[入力とIMEの仕様](../input-ime.md)

完了条件は、パディング0と正の値をドライバーで切り替え、表示倍率1倍・2倍で四辺の幅を確認できることです。先頭セルと最終セルを操作でき、余白をクリックしたときの判定はセル領域の外になります。小さなウインドウでも座標や行数・桁数が不正にならないことを確認します。

## 30.4 縦方向の端数を上か下に置く

横方向は左寄せ、縦方向の既定は上寄せです。下寄せを選べるようにし、固定パディングを除いた高さをセルの高さで割ります。余った画素を加える側は、上寄せなら下、下寄せなら上です。例えば表示倍率1倍でパディングが4 px、縦の端数が7 pxなら、下寄せ時の余白は上11 px、下4 pxです。横の端数は右に残ります。

セルの整数倍にならない寸法をGTK3のドライバーに割り当て、上寄せと下寄せを切り替える試験を先に作ります。配置だけを変えたとき、切り替え前後で行数と桁数は同じです。文字の選択、端末へ送るマウス座標、リンク、IME候補は新しい原点に追従させます。最大化・タイル配置やズームの途中でも、毎回の実寸から同じ規則で端数を求めます。[ホストとの寸法調整](../host-integration.md)・[GTK3のレイアウトAPI](../../../include/boxrig/gtk3/terminal_widget.h)

完了条件は、端数が0なら両方の配置が一致し、端数があれば上辺と下辺の実測値が入れ替わることです。X11とWayland上のGTK3でCairo・OpenGLの出力を調べます。画像で照合するのは、部分更新後に旧位置の文字やカーソルが消え、クリックと選択の結果が描画と一致することです。連続ズームや最大化・復帰の途中は動画で確認します。

## 完了とelder-termsへの引き渡し

各段階では失敗する動作試験（RED）を確認し、変更後にその試験が通ること（GREEN）を確かめてコミットします。公開APIと利用者向けの説明に記載するのは、既定値、単位、セルの原点、余白の扱いです。最終段階で`make test`による全体試験を実行し、各段階の完了条件と照合します。elder-termsのplan29には、検証したコミット、使用する公開API、設定を省略したときの結果を引き渡します。

## 実装と検証の記録

調査時点の `origin/develop`（`0fb7d5f`）から実装しました。ウインドウの縮小待ちを扱う修正は`42c3974`に含まれます。elder-termsに取り込んだリビジョンは同アプリのplan29に記録します。

| 段階 | 変更と検証 |
| --- | --- |
| 30.1 | 文字方向を省略した場合の既定値を`LOGICAL`に統一しました。ヘブライ文字を含む行で、描画、クリック、選択コピー、ブロックカーソルが同じセルを指すことを確認しました。 |
| 30.2 | VS16の既定値を`PRESERVE`に変更しました。絵文字幅を明示した場合は2列に広がり、幅を保つ場合は元の列数になることを端末と入力メソッドの試験で確認しました。 |
| 30.3 | 共通ビューとGTK3に四辺のパディングを追加しました。GTK3はDIPを受け取り、公開レイアウト結果はセル領域の原点を返します。余白から始めた操作は端末のマウス報告から除きます。 |
| 30.4 | 上寄せ・下寄せを切り替えても行数と桁数を保ちます。CairoとOpenGLで先頭セルの画素、端数の位置、再描画とクリックを照合しました。フォントの縮小に合わせてウインドウが縮む途中は先頭行の位置を保ち、ホストがサイズを制限した場合に確定した端数を上に移します。 |

GTK3のサンプルは`BOXRIG_GRID_PADDING=4`と`BOXRIG_GRID_ALIGNMENT=bottom`で試せます。GTK3の共有SDKから配置APIを呼び出せることも確認しました。

デスクトップ右辺へのタイル配置を調べたところ、`origin/develop` の `b677ea6` ではX11版、GTK4版、ネイティブWayland版の起動時に `bottom` の指定が反映されていませんでした。この3版にも設定を適用しました。X11ではKWinのタイル配置に加え、Mutterでタイトルバーを画面右辺へドラッグし、最終行が下端に揃うことを確認しました。

WaylandではSwayで右半分への配置、全画面化、元のタイルへの復帰を試しました。653×739ピクセルの右タイルでスクロールバーを隠すと、93列52行を表示します。下寄せの余白は上に11ピクセル、右に2ピクセルです。スクロールバーを表示した場合も、表示倍率を2倍にした場合も、下端の余白は0でした。Westonでは、起動時に割り当てられた行数を子プロセスが受け取ることと、最終行の背景色を変えると下端まで塗り替わることを確認しました。

端末のリンクを扱うOSC 8の試験では、絵文字を2セルに広げたときに両方のセルが同じリンクを指すことを確認しました。Cairoの部分再描画では、論理順と双方向テキストの視覚順をそれぞれ指定し、全体を描き直した画像と画素を照合しました。

Windows 11（ビルド26200.9974）の実機では、GDI描画のカーソル検証が64ビット・32ビットの両方で成功しました。Wineでは表示倍率を上げた絵文字カーソルの画素が、同じ試験のコントラスト基準に届きませんでした。
