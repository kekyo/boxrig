# plan16 退役行の装飾削除APIをLinux共有ライブラリから公開する

作成日：2026年10月29日

状態：問題の所在と最小の修正を特定しました。製品コードの修正、リリース、elder-termsへの再反映は未実施です。

## 目的と範囲

`boxrig_ui_view_clear_text_annotation_line()`を、公開ヘッダーに沿ってLinuxの共有ライブラリから利用できるようにします。この関数は、指定した登録元と論理行の装飾を削除します。登録元は、装飾を追加した認識器などを識別するIDです。画面幅による折り返しをつなげた本文の行を論理行、その行が履歴から押し出されて本文から消えたものを退役行と呼びます。

この関数は退役行にも呼び出せ、別の行や登録元の装飾は残します。現在のヘッダーは、無効なキーに`BOXRIG_UI_INVALID_ARGUMENT`を返すこと、削除対象がない場合も`BOXRIG_UI_OK`を返すこと、メモリーを確保しないことを約束しています。[公開APIの索引](../reference/api.md)と[引数・戻り値の契約](../../../include/boxrig/ui/view.h)が根拠です。

elder-termsは履歴行の押し出し通知を受けたとき、この関数で該当行のリンク装飾だけを消す計画でした。しかしboxrig 0.9.0の共有ライブラリへリンクできないため、認識器全体を再登録する従来の処理を維持しています。本計画では、共有ライブラリの公開漏れと、その見逃しを防ぐ試験を対象にします。装飾削除の内部動作を作り直す計画ではありません。

基準は0.9.0の`1f0ceeef931e8253e255aa2cd6f5ba822d82d05d`と、調査時点の`develop`である`8f9fbbfbdc9f4b7ad5ff49d341c8279acedb7474`です。作業先はboxrigの`feature/plan16`です。バイナリの利用側との接続規約をABIと呼びます。今回は既存の`BOXRIG_0`という共有シンボルの版へ追加し、ライブラリのABI番号は変更しません。以下のSDKは、利用側が使うヘッダー・ライブラリ・リンク設定のセットを指します。

## 確認した原因

[公開ヘッダー](../../../include/boxrig/ui/view.h)に関数の宣言と契約があり、[実装](../../../src/ui/view.c)にも定義があります。静的ライブラリ`libboxrig-ui.a`の公開シンボルにも存在します。一方、Linux共有ライブラリの[公開シンボル一覧](../../../packaging/linux/boxrig-ui.map)には名前がありません。この一覧をリンカーの版スクリプトとして使う[共有ライブラリの規則](../../../packaging/linux/rules.mk)により、実装は共有ライブラリの利用側へ公開されていません。

0.9.0のヘッダーで利用側のCプログラムをコンパイルすると成功し、同版の共有ライブラリへリンクすると未定義参照で失敗しました。[版とライブラリのハッシュ](../../../artifacts/plan16/export/provenance.json)は、elder-termsの更新時に保存した0.9.0の実物と一致します。[0.9.0のリンク失敗](../../../artifacts/plan16/export/link-release090.log)を記録しました。

現行`develop`でも、公開ヘッダーと静的ライブラリには関数がある一方、共有ライブラリの動的シンボル一覧にはありません。[現行版のリンク失敗](../../../artifacts/plan16/export/link-before.log)でも同じ未定義参照を確認しました。`view.h`内の97件の関数名をこの公開シンボル一覧と照合すると、欠けているのは今回の1件でした。この照合は`view.h`に限ったもので、ほかの公開ヘッダーを含む全ABIの監査結果ではありません。[照合結果](../../../artifacts/plan16/export/audit.json)に名前を保存しています。

原因を分けるため、製品コードは変更せず、公開シンボル一覧のコピーにこの関数名を1行追加しました。共有ライブラリに使える位置独立コードとして構築済みの静的ライブラリから、共有ライブラリだけを再リンクしています。その結果、動的シンボルに`boxrig_ui_view_clear_text_annotation_line@@BOXRIG_0`が現れ、同じ利用側プログラムのリンクが成功しました。関数にNULLの表示先を渡した実行結果も、公開契約どおりの`BOXRIG_UI_INVALID_ARGUMENT`でした。この実行の終了コードは1であり、検証用プログラムが結果値をそのまま返したものです。[差分を入れた一覧のコピー](../../../artifacts/plan16/export/boxrig-ui-with-line-clear.map)と[動的シンボルの比較](../../../artifacts/plan16/export/audit.json)を保存しています。

さらに、既存の[退役行の機能試験](../../../tests/test_annotation_eviction.c)を公開ヘッダーだけでコンパイルし、共有ライブラリへリンクしました。現行版のままでは[リンクに失敗](../../../artifacts/plan16/export/test-eviction-link-before.log)します。一覧のコピーを使って再リンクした共有ライブラリでは、同じ試験を変更せずにリンク・実行できました。結果は[退役行を削除して別の登録元を残す機能試験の成功](../../../artifacts/plan16/export/test-eviction-run-after.log)です。[再実行コマンド](../../../artifacts/plan16/export/test-eviction-commands.txt)も保存しました。この対照実験では、実装を変えなくても公開一覧の1行だけで失敗が解消しました。

## 既存試験が見逃した範囲

[退役行の機能試験](../../../tests/test_annotation_eviction.c)は、現在の[Makefileの規則](../../../tests/performance/recognition.mk)では静的ライブラリにリンクします。対象行が退役しても削除できること、別の登録元や行の装飾が残ることは確認しますが、共有ライブラリの利用側から呼べるかは確認しません。

[共有SDK試験](../../../tests/shared/check_base.sh)は再配置した共有ライブラリをC99・C++20の利用側から呼びます。ただし、利用側が呼ぶAPIは一部に限られ、退役行の装飾削除を含みません。[公開契約の一覧](../../../tests/frontend_public_contracts.def)には関数名が登録されていますが、ここで確認するのは宣言の分類であり、共有ライブラリの動的シンボル一覧との一致ではありません。したがって、既存試験が成功しても今回の公開漏れを検出できません。

## 段階ごとの修正計画

各段階で動かせる成果物を残します。コード修正に着手する際は、先に利用者から観測できる失敗を試験へ加えます。修正前の失敗をRED、修正後の成功をGREENとして記録します。試験と修正は適切な単位で`chore:`、`fix:`のコミットに分けます。

### 第1段階 共有SDKの試験で公開漏れを再現する

`tests/shared/check_base.sh`が再配置した共有SDKに対して、既存の`tests/test_annotation_eviction.c`をコンパイル・リンク・実行するようにします。この試験は、退役行と別の登録元・画面を用いるため、単なるシンボル名の照合ではなく、利用側から見える機能を確認できます。C99とC++20で使う既存の`tests/shared/consumer.c`にも、この関数を一度呼び、戻り値を厳密に確認する処理を追加します。両言語から公開ヘッダーと共有SDKを使う経路を合わせて検証します。

共有SDKを再配置して対象試験を実行し、追加した検証が未定義参照でREDになることを確認します。静的リンクで動く既存の機能試験は、そのまま成功することも確認します。この段階では公開シンボル一覧を変更しません。

完了条件は、共有SDKのC99・C++20の利用側と退役行の機能試験が、今回の欠落を理由に失敗することです。失敗したリンク行と試験ログを保存し、既存の機能試験の振る舞いが修正前にも成立していることを示します。

### 第2段階 公開シンボルを追加して利用側を動かす

`packaging/linux/boxrig-ui.map`の`BOXRIG_0`へ、`boxrig_ui_view_clear_text_annotation_line`を1件追加します。内部の削除処理、APIの引数、戻り値は変更しません。まず第1段階でREDになった共有SDK試験を再実行し、C99・C++20の利用側、退役行の機能試験をGREENにします。生成した`libboxrig-ui.so.0`の動的シンボル一覧にも、対象名が公開されることを確かめます。

完了条件は、共有ライブラリの利用側で退役行の装飾を削除でき、別の登録元・行の装飾が残ることです。C99・C++20の利用側が同じ公開APIを呼び、未定義参照がなく、対象シンボルが`BOXRIG_0`で公開されることも確認します。この成果物を小さな`fix:`コミットにします。

### 第3段階 配布形態と全体試験を確認する

再配置した共有SDKと静的SDKの両方で、C99・C++20利用側を実行します。現在の静的SDK試験はC99だけなので、同じ利用側ソースをC++20でもリンク・実行する確認を追加します。共有SDKでは退役行の機能試験を必ず実行し、静的SDKでは既存の機能試験を維持します。`make test`を全体で実行し、失敗・スキップ・ビルド警告を分けて記録します。時間がかかる試験も、完了条件の判定では省きません。

完了条件は、共有・静的の両配布形態で公開契約を満たし、全体試験で今回の変更に起因する失敗がないことです。失敗が残る場合は原因と影響範囲を特定し、成功扱いにしません。結果を計画へ追記し、必要なドキュメント変更とともに`doc:`または`chore:`コミットへ保存します。elder-termsでの行単位削除への切り替えは、その後に別の作業として検証します。

## 調査したほかの残件

elder-termsのSSHプロキシ試験では、gateway側の試験用サーバーが`ssh_disconnect()`中にSIGSEGVで終了しました。ただし試験実行ファイルにはboxrigの共有ライブラリ依存も静的シンボルもなく、libsshを使用しています。[依存と失敗箇所の記録](../../../artifacts/plan16/ssh-ownership/audit.json)により、この試験の失敗は本計画のboxrig修正対象から外します。libsshと試験側の後片付け処理のどちらが根因かは未確定です。

### 矩形選択はelder-termsの古いヒット結果の扱いに起因する

マウスの座標から文字位置を求めた結果をヒット結果と呼びます。結果には、その時点の文字配置を識別するレイアウト世代が含まれます。elder-termsは押下時のヒット結果を保存し、マウスが一定距離を動いた時点で、その結果を使って選択を開始しています。

製品コードを変更せず、通常・矩形、全画面・上部領域、Cairo・OpenGLを組み合わせたGUI試験8条件を反復しました。[9回目](../../../artifacts/plan16/selection/repeat-9.log)でOpenGLの矩形2条件が失敗し、全画面ではスクロール位置176、上部領域では179から動きませんでした。先行する8回は全条件成功です。この反復は、長い全体試験を繰り返さなくても同じ停止を再現できることを確認するために行いました。

次に、elder-termsのソースを別ファイルへ複製して観測ログだけを加え、診断用の実行ファイルで同じ試験を行いました。2回目の上部領域・OpenGL矩形で、押下時のレイアウト世代126が、画面外へのドラッグ時には150へ変わっていました。保存した押下結果を渡す`boxrig_ui_view_begin_selection_with_options()`は`BOXRIG_UI_STALE`を返しています。その直後にelder-termsが選択を取り消し、自動スクロールのタイマーを開始しないため、位置179のまま止まったことを[診断ログ](../../../artifacts/plan16/selection/diagnostic-failure.stderr.log)で確認しました。

[マウス配送の公開契約](../../../include/boxrig/ui/input.h)には、入力をキューに保持する環境ではヒット結果を値として保存し、後の文字配置変更によってその世代が古くなることが明記されています。[矩形選択の公開API](../../../include/boxrig/ui/view.h)も`STALE`を返し得る契約です。[矩形境界の検証](../../../src/ui/view.c)では、ヒット結果と現在の表示先の世代が異なる場合に拒否します。したがって、観測した`STALE`はboxrigの契約に沿う動作です。

対照実験では、診断用の実行ファイルだけで、`STALE`のときに押下座標のヒット結果を取り直して選択を開始しました。5回目に、旧世代127から現世代151への変化を捕捉しています。論理行ID、行の版2、論理列0は取り直す前後で同じでした。古い結果では`STALE`、新しい結果では`BOXRIG_UI_OK`となり、[同じ8条件すべてが成功](../../../artifacts/plan16/selection/fresh-success.log)しました。[旧結果と新結果の比較](../../../artifacts/plan16/selection/fresh-success.stderr.log)、[試行一覧](../../../artifacts/plan16/selection/fresh-repeats.json)、動画によるスクロール確認の記録も`artifacts/plan16/selection/`に保存しました。

直前のホイール操作によるOpenGLの行レイアウト公開が世代を進めた可能性があります。[OpenGLの公開処理](../../../src/opengl/renderer.c)と[表示先の保存処理](../../../src/ui/view.c)には、その更新経路があります。ただし今回、世代を進めた呼び出し自体は計測していないため、この更新契機は推論として残します。

今回再現した停止は、elder-termsが古いヒット結果で遅れて選択を開始し、`STALE`を受けて操作全体を取り消すことに起因します。boxrig側で古い世代を無条件に受け入れる修正は、本計画へ含めません。対照実験で比較したのは上記の位置属性で、画面や文字の境界側など、全属性の一致までは検証していません。座標を取り直すだけでは本文変更後に別の文字を選ぶ場合があるため、この処理も製品修正としては採用していません。elder-terms側で、押下対象の同一性を確かめて継続する設計と再現試験が必要です。診断用の変更を製品へ適用せず、一時的な試験ファイルも撤去しました。
