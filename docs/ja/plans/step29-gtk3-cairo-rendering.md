# GTK3 Cairoで連続出力を描画する間隔とWaylandでの測定結果

2026年11月20日、GTK3 Cairoで `notcurses-demo` の罫線デモ `grid` を実行したところ、描画間隔の変更で完了時間が15.38秒から6.16秒に短くなりました。前回は同じデモで、GTK3 CairoがネイティブWaylandのCairoの約2倍の回数、画像を準備していました。[前回の測定](step28-wayland-rendering-performance.md)

## 描画間隔の変更

GTK3ウィジェットは、子プロセスの出力から次の画面を用意する時間を、GDKが見積もったディスプレイの更新周期と比べます。1周期以上かかったときだけ、完了からもう1周期ぶんの出力をまとめて次の画像を描くようにしました。その間に同じセルが複数回変わると、画面に出るのは最後の状態です。端末への問い合わせには待ち時間中も応答し、キー入力や貼り付けがあれば通常の描画タイミングに戻ります。[GTK3ウィジェットの公開API](../../../include/boxrig/gtk3/terminal_widget.h)・[GDKの更新周期の取得](https://docs.gtk.org/gdk3/method.FrameClock.get_refresh_info.html)

## 実アプリでの比較

比較元は `4c5b15c6`、変更後は `82489b19` です。前回と同じGNOME Waylandの実機で、GTK3 Cairoを1ウィンドウずつ起動しました。内蔵ディスプレイは90 Hz、表示倍率は150%、電源プロファイルは `balanced` です。端末サイズは118列×45行、1セルは14×28画素です。罫線は既定の保守的方式、文字のアンチエイリアスはシステム標準にそろえました。各条件を3回、実行順を入れ替えて測りました。表は中央値、括弧内は最小値と最大値です。

| 負荷と測定項目 | 変更前 | 変更後 |
| --- | ---: | ---: |
| `grid` 完了時間 | 15.38秒（15.25～16.00） | 6.16秒（6.08～6.36） |
| `grid` 端末のCPU時間 | 15.21秒（15.09～15.85） | 5.86秒（5.82～6.09） |
| `btop -u 100` 受信1更新あたりの端末CPU時間 | 16.53 ms（16.22～16.61） | 16.36 ms（14.12～16.95） |
| `btop -u 2000` 端末のCPU使用率 | 0.75%（0.75～1.00） | 0.83%（0.67～0.83） |
| `xray` 完了時間 | 15.56秒（15.53～15.56） | 15.58秒（15.58～15.59） |
| `xray` 端末のCPU時間 | 8.54秒（8.51～8.54） | 8.51秒（8.50～8.51） |

`grid` と画像デモ `xray` には、それぞれ `notcurses-demo -c -d 0.03 g`、`notcurses-demo -c -d 0.03 x` を使いました。CPU時間は `boxrig_term` のユーザー時間とシステム時間の合計です。`btop` は最初の出力を確認して4.25秒待ち、続く12秒間に100 ms設定で118～119更新、2秒設定で6更新を受信しました。CPU使用率は1コアを100%としています。`xray` が送った画像数の中央値は310枚から308枚に変わりました。`btop` の100 ms設定ではCPU時間の差が試行ごとのばらつきに収まり、`xray` の完了時間は中央値で0.02秒延びました。

## 連続描画中の変化

ここで数えた同期更新は、デモが制御シーケンスで開始と終了を指定した1組の出力です。`grid` に計測を加えた別の各3試行では、デモが送った同期更新は毎回769回で、変更後の最後の画像には769回目までの出力が反映されています。1回の実行でCairoが画像を準備した回数の中央値は758回から356回に、描画関数のCPU時間は12.66秒から4.04秒に減りました。

画像の準備が完了してから次の画像の準備が完了するまでの間隔は、95パーセンタイル（p95）で26.6 msから36.1 msに延びました。これは各試行のp95の中央値です。

実際の画面更新は、別の各3試行でGNOMEがWaylandのウィンドウに返した提示時刻から数えました。デモの実行中に画面に出た枚数の中央値は747枚から331枚に減り、1秒あたりの提示数は46.8枚から51.3枚に増えました。提示間隔のp95の中央値はどちらも33.3 msでした。長い間隔もあり、3試行で観測した最長は変更前100.0 ms、変更後155.6 msでした。変更後の155.6 msの区間では、コンポジターが途中の3枚を破棄したと通知しました。

提示数を数え漏れていないか、変更前後の各1試行でWaylandの通信記録とも照合しました。測定区間に新しいバッファを提出した回数は変更前766回、変更後325回で、いずれもすべての提出に対して提示通知を要求していました。

## 同じ入力を再生したときの画素と遅延

保存済みの `grid`、`btop`、`xray` から各24更新を選び、画面上で識別できるよう各更新に色の目印を加えました。変更前後の端末に同じデータを100 ms以上の間隔で送りました。Cairoが描いた画面全体のSHA-256は、全72更新で一致しました。

遅延は画素ハッシュの計算を外して各3回測りました。単発出力の比較には、100 ms以上の間隔で1セルの背景色だけを変える試験を加えました。表のp95は、アプリが更新を書き始めてからWaylandコンポジターが画面に提示するまでの時間です。最初の更新を除き、提示時刻が返ったものから各試行のp95を求め、その中央値を取りました。括弧内は最初を含む72更新のうち提示を確認できた件数です。提出後にコンポジターが破棄した更新は提示時刻を得られません。端末側ではどの条件でも全72更新の描画が完了しました。[Waylandの提示時刻プロトコル](https://gitlab.freedesktop.org/wayland/wayland-protocols/-/blob/main/stable/presentation-time/presentation-time.xml)

| 固定入力 | 変更前の提示p95 | 変更後の提示p95 |
| --- | ---: | ---: |
| `grid` | 56.8 ms（69/72） | 58.1 ms（72/72） |
| `btop` | 37.9 ms（60/72） | 36.5 ms（62/72） |
| `xray` | 43.8 ms（72/72） | 43.3 ms（72/72） |
| 単一セル | 30.4 ms（63/72） | 27.8 ms（61/72） |

## XWaylandでの速度とキー入力

同じデスクトップのXWayland上でもGTK3 Cairoを測りました。端末は118列×45行のまま、1セルは7×14画素です。`grid` の完了時間は3試行の中央値で10.59秒から3.69秒に、端末のCPU時間は10.36秒から3.36秒に短くなりました。

キーを押して子プロセスが返した1文字がウィンドウに現れるまでのp95は、3試行の中央値で33.7 msから30.4 msでした。変更前後とも毎回24回の画面変化を録画し、各更新の順序と動画のフレーム時刻を検証しました。`grid` の固定入力でも、前後各1回の録画で24更新を確認しています。[固定入力とキー入力の動画検証](../../../tests/performance/check_frame_latency.mjs)

## 回帰テスト

GTK3の描画テストはXvfbとWestonで実行しました。遅い描画の直後に出力を続けて送り、端末が即座に応答すること、次の描画に最後の色が反映されること、貼り付け時には待ち時間中でも次の再描画にエコーを反映できることを検証しました。連続出力中にリサイズと入力を行うGTK3の動画試験でも、75フレームの録画で状態の順序を確認できました。[GTK3の描画テスト](../../../tests/gtk3/test_gtk3_rendering.c)・[連続出力とリサイズの動画試験](../../../tests/run_continuous_output_video.mjs)

全体テストはXvfb用に `WAYLAND_DISPLAY` を外し、同じデスクトップのXWaylandの認証情報を使って `make -k -j1 test` を実行しました。失敗した依存ターゲットは `test-win32-core-artifacts` の1件です。amd64版のテスト実行ファイル `test_graphics.exe` が参照する `msvcrt.dll` の `strstr` が、最低対応OS用の許可一覧に登録されていません。変更前にも同じ検査で失敗しています。Makeは残りの依存ターゲットを実行し、最後の `test` 本体には進まず、終了コード2を返しました。[変更前の記録](plan27-btop-notcurses-rendering-performance.md#テストと計測記録)

この作業ツリーの測定用プログラム、生データ、動画は `artifacts/step29-cairo/` にあります。`node artifacts/step29-cairo/tools/summarize.mjs` で実アプリ、描画関数、固定入力、動画の測定値を、`node artifacts/step29-cairo/tools/surface-summary.mjs` で連続描画中の提示数と間隔を確認できます。
