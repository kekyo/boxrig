# step19 notcurses-demoによる描画と性能の改善

作成日：2026年11月15日

状態：調査・実行中。

## 目的と対象

notcurses-demoをboxrigで実行し、表示の崩れや想定と異なる描画、速度の問題を調査して修正します。開始時点はdevelopの`0abaeed`で、作業ツリーに変更はありませんでした。作業ブランチは`feature/step19-notcurses`です。外部依存コードは変更せず、mainへのマージは行いません。

まず付属ターミナルのGTK3版でCairoとOpenGLを比較します。端末の制御シーケンスを処理するcore、画像処理、文字の配置、描画、表示予約を切り分けます。共通コードを変更した場合は、GTK4やネイティブ描画など、そのコードを使う構成の既存試験も実行します。

導入済みのnotcursesは3.0.7で、パッケージは`3.0.7+dfsg.1-1ubuntu5`です。実行条件は[同バージョンのデモ実装](https://github.com/dankamongmen/notcurses/blob/v3.0.7/src/demo/demo.c)と[公式説明](https://github.com/dankamongmen/notcurses/blob/v3.0.7/USAGE.md)で確認します。生ログ、録画、比較用の実行ファイルはGit管理外の`artifacts/step19/`に保存します。

## 第1段階 再現と基準値の取得

固定乱数種の`notcurses-demo -c`を使い、全デモの成否と描画を調べます。待ち時間の倍率を指定する`-d`、結果をJSONへ保存する`-J`を使い、ウィンドウ寸法、文字セル寸法、フォント、端末種別、描画方式を記録します。Xvfb上の試験と実デスクトップの性能は分けます。

表示の崩れがある場面は録画から取り出し、デモが送った文字・制御シーケンスと期待する画面を照合します。画像の欠落、位置ずれ、前の画面の残像、文字幅や色の違いを調べます。必要なら参照用端末でも同じ場面を実行しますが、端末ごとの機能検出によって出力が変わる点を区別します。

速度はデモ全体の経過時間だけで判定しません。描画待ちやメディアの再生時間、入力解析、画面更新、画像転送などを分け、遅い場面を再実行できるドライバーを用意します。性能比較は同一条件で複数回、逐次実行し、ビルドや全体テストを重ねません。

完了条件は、実行手順、基準値、問題が現れる場面と原因候補を保存することです。調査結果から次の段階の修正対象と検証方法を本書へ追記し、製品コードの修正前に確定します。

## 第2段階 描画の修正

確認した問題ごとに、実際の入力や画面を使った最小の回帰テストを追加します。修正前に失敗するREDを確認し、その原因だけを直してGREENを確認します。複数の原因は別の変更として扱い、各変更でビルドと試験を実行できる状態を保ちます。

画面の内容、位置、色、重なり、消去後の結果を検証します。時間によって現れる欠落や残像は動画を記録し、フレームの順序と内容を検証します。新しい基準画像は目視します。外部ライブラリのAPIを追加利用する場合は、公式文書とAPIコメントの両方を確認します。

完了条件は、確認した描画不具合の再現テストがGREENとなり、notcurses-demoの該当場面でも修正を確認できることです。依存ライブラリや試験環境に由来する制限は、出典と観測結果を分けて記録します。

## 第3段階 処理負荷の改善

第1段階で特定した負荷に対し、処理量または資源使用量を検証するテストを追加します。短い実行時間のしきい値だけに依存せず、同じ描画結果を維持したまま不要な処理を減らします。RED、修正、GREENの順に実施し、採用した変更ごとに性能を比較します。

完了条件は、変更前後の表示が正しく、繰り返し測定で改善量を説明できることです。CPU時間、デモの完了時間、画面への反映時間は区別します。効果が確認できない案は採用しません。原因が変わった場合は計画を見直し、不要になった変更を残しません。

## 第4段階 総合検証と完了判定

修正後のnotcurses-demoを全デモで再実行し、CairoとOpenGLの結果を照合します。変更した経路の回帰テストに加え、`make -j1 test`で全体テストを実行します。長時間の試験はログへ保存し、タイマーを使って確認間隔を空けます。警告、失敗、スキップの理由を調べ、今回の変更による問題は解消します。

各段階の成果は`doc:`、`fix:`、`refactor:`、`chore:`などのヘッダーで適切な粒度にコミットします。最後に各段階の完了条件を実際の成果物と照合し、測定結果、修正内容、テスト結果、残る制限を本書に記録します。一般ドキュメントから本計画へのリンクは追加しません。

全体の完了条件は、notcurses-demoによる評価、問題の分析と計画、根拠のある描画・性能修正、再現テストと全体テスト、結果の記録が揃うことです。未確認の描画や未実施の試験を成功とは扱いません。
