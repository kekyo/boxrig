# plan17 LinuxリリースSDKの共有ライブラリを揃える

作成日：2026年10月29日

状態：第1・第2段階を完了し、第3段階の実装とホスト環境での検証も完了しました。GTK4 4.18以降での背景効果の検証と、第4・第5段階が残っています。

## 目的と範囲

LinuxのリリースSDKに含まれるライブラリのうち、静的ライブラリだけを提供している9種類に共有ライブラリを追加します。SDKは、利用側が使うヘッダー・ライブラリ・リンク設定のセットです。静的ライブラリは`.a`、共有ライブラリは`.so`として配布します。

既存の6種類と合わせ、Linux SDKの全15種類で共有リンクを選べるようにします。静的ライブラリも引き続き同梱します。対象は共有版の生成、インストール、リリースへの同梱と、利用側からの動作確認です。

## 現状と調査の根拠

調査時点のブランチは`develop`、コミットは`c8fb78b`です。[共有ライブラリの生成規則](../../../packaging/linux/rules.mk)には、基礎4種類とGTKの2種類が定義されています。[SDK生成スクリプト](../../../packaging/build_sdk.sh)は、Linux向けに`native shared`をビルドし、`install-shared`で共有版も同梱します。一方、[Makefile](../../../Makefile)の`make native`単独では共有版を生成しません。

| 現在の配布形態 | ライブラリ名 |
| --- | --- |
| 静的版と共有版 | `libboxrig`、`libboxrig-ui`、`libboxrig-session`、`libboxrig-posix`、`libboxrig-gtk3`、`libboxrig-gtk4` |
| 静的版のみ。第1段階で共有化 | `libboxrig-x11`、`libboxrig-wayland` |
| 静的版のみ。第2段階で共有化 | `libboxrig-render-ogl`、`libboxrig-x11-ogl`、`libboxrig-wayland-ogl` |
| 静的版のみ。第3段階で共有化 | `libboxrig-notification`、`libboxrig-background-wayland`、`libboxrig-background-gtk3`、`libboxrig-background-gtk4` |

ローカルに保存された次のアーカイブの内容を確認し、既存6種類の`.so.0`実体と`.so`リンクが含まれることを確認しました。0.9.21のアーカイブでは、追加対象9種類は`.a`だけです。この調査は手元のファイルを対象とし、公開先の全アーカイブを検証したものではありません。

- `artifacts/boxrig-0.9.0-linux-ubuntu-24.04-x86_64.tar.gz`
- `artifacts/boxrig-0.9.21-linux-x86_64.tar.gz`

既存の共有版は、共有ライブラリに使用できる位置独立コード（PIC）を通常の静的ビルドと分けて生成します。既定の出力先は`build/shared/`です。公開シンボル一覧で利用側へ公開する関数を指定し、実行時に識別するライブラリ名（SONAME）には`libboxrig.so.0`などを使っています。この末尾の番号はバイナリの接続規約（ABI）を表し、パッケージのリリース番号とは独立しています。

## 実装と検証の方針

既存のPICビルド、公開シンボル一覧、SONAME、インストール規則を拡張します。追加する共有版も`.so.0`を実体とし、リンク時に使う`.so`をその実体へのリンクとして配置します。pkg-configは、利用側へコンパイル・リンク設定を渡す仕組みです。各ライブラリの`.pc`ファイルで、共有リンクと静的リンクに必要な依存情報を整理します。

各段階では先に利用側の試験を追加し、共有版が使えないことによる失敗をREDとして確認します。その後に対象ライブラリを実装し、同じ試験が成功することをGREENとして確認します。ファイルやシンボルの存在確認だけでなく、公開ヘッダーを使うプログラムをビルド・実行し、機能を検証します。各段階の成果物は、後続の段階を待たずに利用・検証できる単位にします。

ライブラリ間の内部シンボルへの依存も調べ、利用者向けの公開APIと区別します。共有化に伴ってboxrigのコードが重複して静的に取り込まれたり、未解決シンボルが残ったりしないよう、依存関係を確認します。外部ライブラリやサブモジュールのコードは変更しません。

試験と実装は段階ごとに適切な粒度でコミットし、内容に応じて`feat:`、`fix:`、`chore:`、`doc:`を付けます。計画にない問題が発生した場合は原因と計画への影響を分析し、必要な変更を計画へ反映してから進めます。

## 第1段階 公開APIと依存関係を整理し、X11・Waylandを共有化する

追加対象9種類の公開ヘッダーと実装、ライブラリ間の依存を確認します。その結果に沿って、まず`libboxrig-x11`と`libboxrig-wayland`の共有版を追加します。

利用側のプログラムを公開ヘッダーでコンパイルし、共有リンクする試験を先に追加します。静的版へ自動的にリンクされて成功扱いにならないよう、実際に読み込むライブラリも確認します。共有版がない状態でREDを記録した後、PICビルド、公開シンボル一覧、リンク規則、インストール規則、pkg-config情報を追加します。

生成したSDKを別のディレクトリへ移し、そのSDKだけを参照して利用側をビルド・実行します。既存のWaylandパッケージ試験などを活用し、リンク成功だけでなく、公開機能が動作することを確認します。

完了条件は、再配置したSDKのX11・Wayland共有版を使って利用側をビルド・実行できることです。REDとGREENの記録を残し、既存の基礎4種類とGTK共有版の試験も成功することを確認します。

## 第2段階 OpenGL関連の3種類を共有化する

`libboxrig-render-ogl`、`libboxrig-x11-ogl`、`libboxrig-wayland-ogl`の順に共有版を追加します。各ライブラリについて、共有版を使う描画試験でREDを確認してから生成・インストール規則を拡張します。

内部シンボルへの依存を調べ、必要な内部連携を公開APIと区別して扱います。既存の描画試験を共有リンクでも実行し、描画ライブラリ単体とX11・Waylandの各構成を検証します。

完了条件は、3種類の共有版による描画が成功することです。依存するboxrigライブラリを共有版として読み込み、重複した静的取り込みや未解決シンボルがないことも確認します。

## 第3段階 通知・背景効果の4種類を共有化する

`libboxrig-notification`、`libboxrig-background-wayland`、`libboxrig-background-gtk3`、`libboxrig-background-gtk4`の共有版を追加します。対象ごとに利用側の試験でREDを確認し、共有版の生成とインストールを実装してGREENを確認します。

通知と各環境の背景効果について、既存の機能試験を共有リンクでも実行します。実行環境が機能に対応していない場合の戻り値も、公開APIの契約に沿って検証します。

完了条件は、各共有版から公開機能を実行できることと、非対応環境での結果が契約どおりであることです。対応環境での機能確認と非対応環境での確認を区別して記録します。

## 第4段階 リリース生成へ統合する

各段階で追加した共有版を`shared`と`install-shared`へまとめ、Linux SDKのリリース生成に組み込みます。[リリース生成スクリプト](../../../build_package.sh)と[コンテナ内のビルド処理](../../../packaging/build_linux_container.sh)で使う、事前生成のpkg-config情報とその確認対象も全15種類へ拡張します。

先に、リリースアーカイブから展開したSDKを使う試験を追加し、未同梱の共有版がある状態でREDを確認します。既存のスクリプト試験は模擬ビルドによる検証を含むため、実際に生成したアーカイブを展開・移動し、そこから利用側をビルド・実行する検証も行います。

完了条件は、アーカイブに全15種類の`.so.0`実体と`.so`リンク、静的ライブラリ、公開ヘッダー、pkg-config情報が含まれることです。移動後もリンクが有効で、共有リンクに必要な依存情報が揃い、実行時に依存ライブラリを読み込めることを確認します。SONAMEの番号は既存方針に合わせ、リリース番号と分離します。

## 第5段階 全配布対象と全体テストで検証する

[配布対象の定義](../../../packaging/common.sh)にあるLinuxの9対象で、実際のリリースパッケージを生成します。

| 配布先 | リリース | CPU |
| --- | --- | --- |
| Debian | 13（trixie） | x86_64、i686、arm64、armv7l、riscv64 |
| Ubuntu | 24.04 | x86_64、arm64 |
| Ubuntu | 26.04 | x86_64、arm64 |

各対象でバイナリのCPU形式、共有ライブラリの依存、共有リンク、利用側の実行結果を確認します。ホストと異なるCPUでは、その対象を実行できる環境を使います。ビルド成功やファイルの存在だけで、実行確認まで完了したとは扱いません。

既存の`test-shared-base`、`test-shared-gtk`、`test-shared-prebuilt`と、追加した共有版・リリースアーカイブの試験を実行します。静的SDKの利用側も確認した後、最後に`make -j1 test`で全体テストを実行します。ビルド警告は原因を分析して対処し、失敗・スキップと分けて記録します。

利用手順は[日本語のビルドガイド](../building.md)を原本として更新し、[英語版](../../en/building.md)へ反映します。共有版の対象、生成・インストール方法、pkg-configの使い方、実行時のライブラリ検索方法を利用者の視点で説明します。本計画書は一般ドキュメントからリンクしません。

完了条件は、全9配布対象で全15種類の共有SDKを利用でき、静的SDKも動作することです。全体テストの失敗が残る場合は原因と影響範囲を特定し、未達条件として明記します。環境上の理由で実行できない項目やスキップも、成功と区別します。

## 作業完了時の照合

実装を終えた時点で、各段階の完了条件と実行結果を本計画へ追記します。対象ライブラリ、配布先、RED/GREEN、利用側の実行、全体テストの結果が対応するよう記録し、未実施や失敗が残る項目は完了扱いにしません。

計画の初回保存時点では、コードと手元のアーカイブを調査しただけで、共有版の追加、リリースの再生成、ビルド・テストは行っていませんでした。

## 実施記録

### 第1段階 X11・Wayland共有SDK

既存の静的SDKへ利用側プログラムをコンパイルし、共有ライブラリを明示してリンクすると、X11・Waylandとも対象の`.so.0`が見つからず失敗しました。[X11のRED](../../../artifacts/plan17/native-red-x11.log)と[WaylandのRED](../../../artifacts/plan17/native-red-wayland.log)を保存しています。

`shared-native`と`install-shared-native`を追加し、専用のPICビルドから2種類の共有版と静的版をインストールできるようにしました。公開ヘッダーにあるX11の161関数、Waylandの63関数を共有版から公開します。再配置できるpkg-config情報と、全体テストに含まれる`test-shared-native`も追加しました。

[第1段階のGREENログ](../../../artifacts/plan17/native-green.log)では、移動したSDKからC99・C++20の利用側をビルド・実行し、既定設定とアニメーション待機アダプターの作成・待機準備・破棄を確認しました。実行ファイルの依存情報にも各共有ライブラリのSONAMEがあります。既存のX11イベント待機試験を共有リンクで実行し、イベント待機・アニメーション期限・PTY入力の処理も成功しました。共有ファイルを外した後のC99・C++20の静的リンクも成功しています。

`make -j1 test-shared-base test-shared-gtk`も成功しました。[基礎・GTKの検証ログ](../../../artifacts/plan17/base-gtk-step1.log)には、SDKの再配置、基礎ライブラリの増分ビルド、GTKのCairo/OpenGL設定切替と共有・静的描画の結果を記録しています。今回のビルドでコンパイラー警告はありませんでした。

第1段階の完了条件は満たしました。全体テストと9配布対象のリリース検証は第5段階で実施します。

### 第2段階 OpenGL共有SDK

静的SDKから3種類の共有版へ明示的にリンクすると、対象の`.so.0`が見つからず失敗しました。[描画ライブラリ](../../../artifacts/plan17/opengl-red-renderer.log)、[X11](../../../artifacts/plan17/opengl-red-x11.log)、[Wayland](../../../artifacts/plan17/opengl-red-wayland.log)のREDを保存しています。

`shared-opengl`と`install-shared-opengl`を追加し、描画ライブラリ、X11 OpenGL、Wayland OpenGLの3種類を生成・インストールできるようにしました。公開ヘッダーの関数は`BOXRIG_0`、コンポーネント間でレンダラーの所有権やIMEを連携する内部関数は`BOXRIG_PRIVATE_0`に分けています。初回の共有リンクで判明した内部関数3件とX11・Fontconfigの依存を明示しました。これは計画で対象とした内部シンボルの依存整理に含まれ、製品の動作は変更していません。

`make -j1 test-shared-opengl`は成功しました。[GREENログ](../../../artifacts/plan17/opengl-green.log)では、再配置したSDKを使ったC99・C++20の共有・静的利用に加え、既存のOpenGL描画例による画素検証が両方のリンク方式で成功しています。X11の既存コンポーネント試験も共有リンクで実行し、画素と表示領域を含む公開機能を確認しました。

Waylandでは、既存の試験から公開APIによる通常の描画手順を抽出した利用側プログラムを追加しました。WestonのGL描画環境で、コンポーネントの作成・領域設定・親への反映・描画・表示完了・破棄を確認しています。成功した画面交換回数、全面再描画回数、表示世代が増加し、描画バッファーの寸法も一致しました。固定回数のポーリングは使わず、未処理の作業を実行した後にサーバーのイベントを待ちます。

各実行ファイルが共有版へ依存すること、追加した共有ライブラリがcore・UIの公開定義を複製せずに共有版へリンクすることを試験で確認しました。[依存関係の記録](../../../artifacts/plan17/opengl-dependencies.json)でも未解決シンボルはありません。コンパイラー警告はなく、Westonのdebug protocol通知は実行時の通知として区別しています。

第2段階の完了条件は満たしました。第3段階では通知・背景効果の共有化を進めます。

### 第3段階 通知・背景効果の共有SDK

既存の静的SDKに対して共有ライブラリを明示してリンクし、4種類とも`.so.0`が見つからず失敗することを確認しました。[通知](../../../artifacts/plan17/effects-red-notification.log)、[Wayland背景](../../../artifacts/plan17/effects-red-wayland.log)、[GTK3背景](../../../artifacts/plan17/effects-red-gtk3.log)、[GTK4背景](../../../artifacts/plan17/effects-red-gtk4.log)のREDを保存しています。

`shared-effects`と`install-shared-effects`を追加しました。X11の共有版は通知とPOSIXの共有版へ、Waylandの共有版は背景効果の共有版へリンクします。GTK3背景効果もX11の共有版を利用し、共有ライブラリ間で同じ提供機能のオブジェクトを重複して取り込まない構成にしました。静的ライブラリの構成は維持しています。

`make -j1 test-shared-effects test-shared-native test-shared-opengl`は成功しました。[GREENログ](../../../artifacts/plan17/effects-green.log)には、再配置したSDKのC99・C++20による共有・静的利用と、依存を変更したX11・Wayland・OpenGLの再検証を記録しています。通知は偽のD-Busサービスが実際に受信したことを確認しました。Wayland背景効果は対応機能の発見・喪失・再広告、領域、commit境界を検証し、GTK3でも静的な画面の反映、非表示からの再表示、機能喪失を確認しています。

GTK4のホスト環境では、[既存の実装](../../../src/background_effect/gtk.c)が4.18未満の分岐を選びます。この環境では非対応を返し、GDKが所有するsurfaceへcommitしないことを確認しました。4.18以降の対応分岐は、後段の配布対象で検証します。pkg-config情報も既存の静的SDKに合わせて両構成を用意し、ビルド対象のGTK4に対応する情報をインストールします。

GTKの利用側試験は既存のGTK試験と同じコンパイラー設定に揃え、ほかの利用側では`-Wpedantic`を維持しました。最終の試験でコンパイラー警告はありません。MesaのDRI3通知は実行時の通知として区別しています。第3段階のホスト検証は成功し、GTK4の対応分岐を含む配布対象ごとの検証は未完了です。
