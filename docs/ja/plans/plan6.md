# plan6: 矩形選択の途中状態と履歴への拡張

## 目的と開始点

boxrigの矩形選択を、幅ゼロを通るドラッグや、スクロールして履歴へ伸ばす操作でも使えるようにする。選択の開始点を保持し、見えている範囲、コピーする本文、公開APIから取得する範囲を一致させる。

計画作成日は2026年10月21日。対象は`~/Projects/boxrig/`で、開始時のHEADは`032efb05894cd8b629f4d340d6353b4ffb2cda0e`、作業ブランチは`feature/plan6`である。開始時の作業ツリーに変更はなかった。

本計画は、elder-termsのlibvteからboxrigへの移行に関する調査を引き継ぐ。調査メモは`~/Projects/boxrig_selection_improvements.md`に保存済みで、本書にも判断の根拠と改善内容を記載する。調査時のelder-termsは`3c8240cd3b0ea8cc2c5761dc8f9c8caeb3c6c0d0`、取り込み済みのboxrigは上記と同じコミットだった。

計画保存時点では、ソース、公開APIのコメント、公式文書、既存テストを読んでいる。問題を実行して再現した結果はまだない。今回は計画の保存までとし、実装、ビルド、テストは開始しない。

## 用語と対応範囲

ブロック選択は、複数行の同じ表示列を選ぶ矩形選択を指す。通常選択は、開始位置から終了位置まで本文の順序でつながる選択である。以降、動かさない開始点をアンカー、マウスに合わせて動かす終点をフォーカスと呼ぶ。

論理行は端末が保持する本文の行で、折り返された論理行は複数の物理行に分かれる。物理行は、画面上では1行として表示される単位である。表示領域をスクロールすると画面内の行番号は変わるが、保持中の本文には同じ論理行IDと折り返し位置で到達できる。双方向文字では、画面の左右の順序と本文の文字順が異なる場合がある。

| 調査で挙がった内容 | 現在の分担とplan6での扱い |
| --- | --- |
| 青い選択枠を灰色の塗りへ変える | 既存の選択スタイルAPIで対応できる。elder-termsで設定する項目 |
| ESCで選択を解除する | 既存の解除APIをelder-termsのキールーターから呼べる。キーとIMEの優先順位もアプリ側で決める |
| 矩形の幅が途中でゼロになる | boxrigの正常な選択状態として扱う。plan6の必須範囲 |
| スクロール後も元の本文から矩形を広げる | boxrigでアンカーを保持し、履歴を含む矩形を構成する。plan6の必須範囲 |
| リンク上からのCtrl＋ドラッグ | elder-termsのリンク起動とドラッグ判定を調整する項目 |
| 画面外へのドラッグによる自動スクロール | ホストがスクロールと終点の更新を行う。plan6では、その呼び出しを受ける矩形選択の基盤を整える |
| 共通の選択操作部品、選択色の反転方式 | 調査で挙げた任意の改善。後述の拡張候補として残す |

塗りつぶしと解除には、すでに`boxrig_ui_view_set_selection_style()`と`boxrig_ui_view_clear_selection()`がある。[装飾の説明](../decorations.md)、[選択API](../../../include/boxrig/ui/view.h)、[スタイルの定義](../../../include/boxrig/ui/decoration.h)に対応する。青い輪郭は現在の既定値で、矩形選択にも同じスタイルが適用される。

固定色の塗りと、libvteでハイライト色を省略したときの前景・背景の反転は別の表示仕様である。[VTEの公式API説明](https://gnome.pages.gitlab.gnome.org/vte/gtk3/method.Terminal.set_color_highlight.html)を参照する。ESCについても、libvte全体に共通する解除専用キーとは断定しない。

elder-termsの実装変更、同リポジトリ内のboxrigサブモジュール更新、SDKの公開、ブランチのマージは本計画の実装範囲に含めない。boxrigで追加する機能は、同リポジトリのドライバーとサンプルで確認できるようにする。

## 現在の問題と根拠

### 幅ゼロになる正常なドラッグが引数エラーになる

[view.c](../../../src/ui/view.c)の`boxrig_ui_view_update_selection()`は、開始した行と列境界の両方に戻った場合だけ、矩形の幅を1セルに補正している。別の行で同じ列境界になった場合は補正しない。続く`materialize_rectangular_rows()`は`first_column >= last_column`を引数エラーとして扱う。

ASCII文字を複数行に置き、セル幅10・高さ20の表示で、座標`(21, 1)`から`(21, 21)`へ更新すると、この条件を検証できる。開始と更新には、それぞれ現在のレイアウトから取得した有効なヒット結果を使う。ヒット結果は、ポインター位置に対応する文字位置とセル境界の情報である。

elder-termsの[マウス処理](https://github.com/kekyo/elder-terms/blob/3c8240cd3b0ea8cc2c5761dc8f9c8caeb3c6c0d0/elder-terms-terminal/src/terminal-runtime.cpp#L148)は、この失敗を入力経路のエラーへ変換する。boxrig側で幅ゼロの契約を整えれば、アプリが正常なドラッグを例外扱いする必要がなくなる。戻り値だけを成功に変えて古い矩形を残す修正は行わない。

### 履歴を含む拡張に画面内の行番号を使っている

現在の`materialize_rectangular_rows()`は、アンカーとフォーカスの画面内行番号の間を列挙する。`last_row >= view->row_count`を拒否し、各行も現在の表示領域から解決する。この構造では、画面の高さを超える矩形を構成できない。

スクロール後の更新でも、保持している`anchor_visual_row`を現在の表示領域の行番号として使う。開始した本文が別の画面内行へ移ると、アンカーを別の本文へ取り違える可能性がある。`rebase_rectangular_selection()`は保持中の本文と改訂を検査するが、更新時の画面内行番号を補正する処理ではない。

[既存の選択テスト](../../../tests/test_selection.c)には、完成済みの矩形をスクロール後も保持する検証がある。ドラッグ中に表示領域を動かしてから矩形を広げる検証とは分けて追加する。

## 採用する動作とAPI契約

### 幅ゼロは、開始点を残した空の選択にする

選択の更新で左右の列境界が一致した場合は、行が同じか異なるかによらず`BOXRIG_UI_OK`を返す。矩形の開始点と終点は保持し、その後に左右へ動かせば同じ開始点から選択を続けられるようにする。更新時に最低1列へ広げる補正は統一して取り除く。

選択開始APIが押した文字を含む範囲を作る現行動作は維持する。クリックだけで解除するか、何ピクセル動かしてから選択を開始するかは、ホストの操作方針として扱う。

| APIまたは観測対象 | 幅ゼロのときの契約 |
| --- | --- |
| `boxrig_ui_view_get_selection()` | `true`。形状、開始点、終点を保持し、`stale = false`、`range_valid = false`とする |
| 選択の列数と保持件数 | `visual_column_count`、`row_count`、`range_count`は0。途中で通過した行数を、空の行スライスとして確保しない |
| 行と論理範囲の問い合わせ | `BOXRIG_UI_OK`、必要件数0。出力配列は不要 |
| 描画と支援技術へ公開する範囲 | 選択範囲は0件。直前の塗りや輪郭も消える |
| `boxrig_ui_view_create_selection_snapshot()` | `BOXRIG_UI_UNAVAILABLE`。出力ポインターは`NULL` |
| コピー要求 | 空の本文で既存のクリップボードを上書きしない |
| `boxrig_ui_view_clear_selection()` | 開始点を含めて解除し、以後の選択問い合わせは`false` |

空の選択は、解除済みの状態と区別する。本文の変更や履歴破棄で開始点を解決できなくなった場合は、通常の無効化規則を適用する。空になったことだけを理由に古い行配列を残したり、無効な開始点を復活させたりしない。

更新前後に必要な描画領域と選択変更通知を更新する。空になった後のボタン解放で、PRIMARYを空文字に置き換えないこともサンプルで検証する。PRIMARYは、中クリック貼り付けなどに用いる選択用クリップボードである。

### アンカーは本文の識別子で保持する

矩形の各端点は、画面の種類、論理行ID、物理行の開始位置、表示列境界で特定する。物理行の開始位置には、論理行の先頭から数えた列オフセットを使う。本文の改訂番号と、選択の列境界を成立させたレイアウト条件も保持して検査する。

現在の画面内行番号や履歴配列の添字は、その都度解決した結果として使う。本文を特定するために、生存期間が端末更新をまたぐ内部ポインターを保持しない。開始点が画面外になっても、その本文が履歴に残る限り同じ端点を指す。

ホストは既存の方法でスクロールし、モデルを同期してから、現在の表示領域に対する新しいヒット結果を渡す。`boxrig_ui_view_update_selection()`は、その終点と保持中のアンカーから矩形を更新する。履歴へ伸ばすためだけの別の更新関数は追加しない。画面外の生のポインター座標を受け付ける契約にも変えない。

レイアウトが後から用意されたことによる世代番号の更新と、列数・セル寸法・折り返しの変更は区別する。有効な現在のヒット結果を受け付けつつ、古いヒット結果や別画面の終点は従来どおり拒否する。

### 画面外の行も同じ矩形の一部として扱う

両端点の間にある物理行を本文の順序で列挙し、各行に同じ表示列区間を適用する。上下のどちらへ伸ばした場合も、問い合わせとコピーでは上から下の順序にそろえる。途中のスクロールで一度も表示しなかった行も含める。

行ごとの文字境界は、画面に表示するときと同じ規則で求める。全角文字、結合文字、絵文字を途中で分割せず、双方向文字の表示列を本文の範囲へ変換する。画面外の行に現在の表示行のレイアウトを流用したり、レイアウトがないという理由で左から右への文字順と仮定したりしない。

[文字レイアウト処理](../../../src/ui/text_layout.c)と、[コアの行・位置・スナップショットAPI](../../../include/boxrig/terminal.h)を使い、必要な物理行の対応関係を得る。表示行向けの処理を共用できる部分は、小さな変更単位で分離する。文字を取得するために端末の表示位置を一時的に動かしたり、レンダラーに非表示行を描かせたりする設計は採らない。

現在の`boxrig_text_layout_create()`は、すでに解析された双方向文字のレベルを入力として受け取る。文字列からの解析は、[Pango/Cairo](../../../src/pangocairo/renderer.c)、[OpenGLの文字プロバイダー](../../../src/opengl/text_provider.c)、[X11](../../../src/x11/renderer.c)、[Win32](../../../src/win32/text.c)などにある。`boxrig_ui_view_store_row_layout()`へ表示行のレイアウトを保存するだけでは、まだ表示したことのない履歴行を解決できない。

このため、物理行の識別子と本文の改訂を指定して、同じ文字解析へレイアウトの作成を委譲できる入口を設ける。UI層には、表示列と本文の対応、所有権、保持量を返し、描画対象やスクロール位置は変更しない。既存の文字解析を再利用する部品は、表示時と履歴選択時でフォント・方向・文字境界の方針をそろえる。公開する場合は、登録・解除の寿命、再入禁止、作成失敗の状態を契約に含める。

キャッシュを使えず、必要な対応関係も作れない場合は、未解決の行を推測して選択へ組み込まない。更新を確定せず理由を返す。ネイティブ部品とSDKの利用例では、対応する解析部品を接続した状態で履歴選択が成功することまで検証する。ドライバーのASCIIだけが成功しても、この項目の完了とはしない。

文字レイアウトの所有者、保持期間、破棄条件を明示する。保持する量は既存の`maximum_retained_layout_bytes`などの制限内に収め、キャッシュから外れた行も再計算できるようにする。選択外の履歴が増えただけで、新しい全文投影やレイアウト処理が増えないことを計数で確認する。

### 公開する行番号に有効性を付ける

現在の`boxrig_ui_selection`と`boxrig_ui_selection_row_slice`には、画面内行番号を表す`size_t`の項目がある。画面外の行を0へ丸めたり、負の行番号を符号なし値へ変換したりすると、利用者が別の行として解釈してしまう。

既存の行番号項目には、現在の表示領域にその行があるかを表す有効性の項目を追加する。対象は開始点、終点、矩形の先頭行、および各行スライスである。有効な場合だけ対応する画面内行番号を参照でき、無効な場合の数値は0とする。フィールド名と構造体の最終形は、ステップ2でヘッダーのコメントとテストに確定する。

行スライスの`row_sequence`は、画面外も含めた矩形全体の先頭から数える。論理行ID、物理行の開始位置、選択した本文の範囲は保持し、画面内位置とその有効性は問い合わせ時の表示領域に対応させる。問い合わせは引き続き呼び出し側の配列へ書き込み、必要件数と容量不足を返す。

この変更に合わせて、「行スライスの全項目が作成時から不変」という説明を更新する。本文の対応関係と、現在の表示位置を区別した契約にする。公開構造体の変更では後方互換性のための別APIを設けず、ヘッダー、利用箇所、SDKのテスト、利用文書を同じ段階で更新する。

### コピー、無効化、容量制限を維持する

描画は現在見えている部分、コピーは選択全体を対象にする。支援技術へ公開する範囲も、同じ選択データから生成する。画面外の本文をアプリだけで集め、コピー結果とboxrigの選択範囲を別々に管理する方法は採らない。

矩形のコピーでは、空白と行末の空白を保持する。物理行の間にはLFを1つ入れ、最後には追加しない。折り返し行もこの物理行単位で区切る。幅広文字を重複出力せず、双方向文字を含む各行は本文の論理順で出力する。取得後のスナップショットは、後続の端末更新や選択変更から独立する。[現在の契約](../text.md)と[コピーAPIのコメント](../../../include/boxrig/ui/view.h)を更新時の基準とする。

| 変更または状態 | 選択の扱い |
| --- | --- |
| 表示領域のスクロール、選択した本文を変えない出力 | 開始点と選択本文を維持する |
| 選択した本文の変更、対象履歴の破棄、折り返しやセル寸法の変更 | 同じ文字を指せない矩形を`STALE`にし、別の本文をコピーしない |
| 主画面と代替画面の切り替え | 別画面へ選択を描画・拡張しない。元の画面へ戻った場合の保持と無効化を既存契約に合わせる |
| 幅ゼロ | 本文の端点が有効なら空の選択として維持する |
| 行・範囲の容量超過、メモリ確保失敗 | 途中までの矩形へ置き換えず、それまでの選択を維持して適切な状態を返す |

容量の既定値と上限は変更しない。物理行は既定4,096行・上限65,536行、論理範囲は既定65,536件・上限1,048,576件、コピーは既定16 MiB・上限256 MiBである。掛け算と加算のオーバーフロー、途中で失敗した確保の解放、空状態からの再拡張も検証する。

## 実装の進め方

各ステップで、問題を操作または公開APIから再現するテストを追加し、修正前の失敗を確認する。その後に必要な変更を加え、対象テストと関連する回帰テストの成功を確認する。ソース中に特定の文字列があることではなく、戻り値、選択状態、コピー本文、描画結果を検証する。

各ステップはビルド可能な成果物と実行可能なドライバーまたはサンプルを残し、適切な粒度でコミットする。公開APIの変更にはdoxygenコメントを付け、日本語の利用文書を原本として対応する他言語の文書も更新する。変更で不要になった補正処理や補助コードは整理する。

### ステップ1: 幅ゼロを通っても選択を続けられるようにする

[test_selection.c](../../../tests/test_selection.c)へ、同じ列境界のまま別の行へ動かす再現テストを加える。開始行へ戻る場合、左右を往復する場合、上下逆向きの場合、空から広げ直す場合も検証する。空の問い合わせ、コピー不可、描画範囲0件、明示的な解除との違いを同じ契約で確認する。

`update_selection()`と矩形の構成処理を修正し、空になった時点で古い行・範囲を解放する。空の開始点が無効になる条件を同期処理へ反映する。コピーや支援技術の処理に、非ゼロ件数を前提とした箇所があれば、空状態を受け付けるようにする。

[サンプルのマウステスト](../../../tests/test_example_mouse_policy.c)では、同じ操作が入力エラーへ変換されず、空のままボタンを離してもコピーを要求しないことを確認する。通常選択、矩形以外の選択単位、無効なヒット結果の検査は維持する。GTK3サンプルでも、上下へのドラッグと再拡張を観測する。

成果物は、幅ゼロの契約を持つAPI、回帰テスト、更新した説明と操作記録である。完了条件は、再現テストが修正前に失敗し、修正後は上下左右の往復、空状態、再拡張、解除がすべて成功すること。コミットは`fix:`を基本とする。

### ステップ2: スクロール後も開始した本文から伸ばす

まず、両端点が画面内に収まる小さなスクロールで、アンカーの取り違えを再現する。例えば、上からD・E・F・Gの行を表示してFから開始し、1行戻してC・D・E・FにしてからDまで伸ばす。期待する範囲はD・E・Fであり、古い画面内行番号が指すEを開始点にしてはいけない。列境界は異なる位置にして、ステップ1の幅ゼロ問題と分ける。

開始点を本文の識別子で保持し、現在の表示領域へ解決してから更新する。公開する行番号の有効性を追加し、完成済みの矩形をスクロールした場合の問い合わせも確認する。本文が同じまま位置だけ変わる場合と、本文自体が無効になる場合を別のテストにする。

公開APIだけで選択開始、スクロール、同期、終点更新、コピーを行う小さなドライバーを`tests/`配下に追加する。Makefileからビルド・実行でき、開始した行、選択全体の行数、取得した本文を確認できるようにする。既存サンプルにテスト用の操作列を追加する場合も、このドライバーと同じ期待結果を使う。

成果物は、スクロールに追従する端点管理、行番号の公開契約、実行可能なドライバーである。完了条件は、両端点が表示中の拡張と、完成済み選択の画面外への移動・復帰で、選択本文と問い合わせの対応が保たれること。履歴全体への拡張は次のステップで完成させる。コミットは`fix:`を基本とする。

### ステップ3: 画面の高さを超える矩形を構成する

ステップ2のドライバーを使い、開始点を画面外へ移した後も矩形を伸ばすテストを追加する。選択行数が画面の高さを超え、コピーに全行が含まれることを修正前の失敗として確認する。上下両方向、開始点をまたぐ縮小と反転、複数画面分を一度に移動する操作を扱う。

本文の物理行を列挙する処理と、表示列から各行の本文範囲を求める処理を接続する。最初はASCIIの矩形を完成させ、その状態を実行可能な成果物として残す。次に、画面外で一度も表示していない行を含む全角文字、結合文字、絵文字、双方向文字、短い行と折り返しを追加する。文字レイアウトの共用が必要なら、その利用例とテストが動く単位で分ける。

描画、行問い合わせ、コピー、支援技術の範囲を同じ選択へ結び付ける。選択対象の編集、履歴の破棄、表示列数やフォントの変更、主画面と代替画面、複数ビューで異なる表示位置も検証する。容量を小さくしたテストと確保失敗のテストで、途中状態へ置き換わらないことを確認する。

処理量は、履歴全体の長さと選択範囲の長さを別々に変えて計測する。レイアウト作成数、投影した行数、保持したバイト数で余分な処理を確認し、実行時間だけの合否基準は設けない。所有メモリはASan・UBSanなど既存の検証方法で確認する。

成果物は、保持中の履歴を含む矩形選択と、公開APIでその結果を観測できるドライバーである。完了条件は、画面外の開始点、未表示の中間行、文字境界、容量制限、無効化を含め、表示範囲とコピー本文が仕様に一致すること。ASCII対応と文字レイアウト対応は、それぞれテストが成功する`feat:`または`fix:`のコミットに分ける。

### ステップ4: ネイティブ表示と配布SDKで確認する

[選択スタイルのテスト](../../../tests/test_selection_style.c)と[描画用の共通テスト](../../../tests/selection_renderer_fixture.c)へ、幅ゼロを通る更新と履歴へ拡張した矩形を追加する。CairoとOpenGLで、見えている部分だけが塗られ、空状態と解除で直前の表示が消えることを確認する。通常選択と矩形選択の両方で、既存の輪郭、塗り、文字色、色補正の結果を維持する。

[既存の動画テスト](../../../tests/run_native_selection_style_video.mjs)を使い、必要な操作列を拡張する。選択開始、幅ゼロ、再拡張、スクロール、解除の順序を記録し、途中で古い枠が残る場合も失敗として検出する。終端の静止画だけで合否を決めない。操作や描画完了を状態で待ち、固定時間の待機だけに依存しない。画像のマスターを追加・変更する場合は目視確認する。

ホストによる履歴操作は、検証用ドライバーまたはサンプルのテスト用操作から呼び出す。ここで共通の自動スクロール部品まで製品実装へ加える必要はない。GTK3、GTK4、X11、Waylandで共有する部分と固有の入力・描画経路を確認し、Win32は既存の検証方針に沿って扱う。

配布ヘッダーからビルドするSDKのテストにも、空状態、行番号の有効性、履歴へ伸びる矩形を追加する。内部ヘッダーやサンプル専用部品に依存せず、利用者が公開APIで同じ結果を得られることを確認する。

成果物は、ネイティブの操作・描画記録、SDKの回帰テスト、更新した利用文書、全体テストの結果である。完了条件は、関連経路の検証が成功し、全体テストの失敗・スキップを根拠付きで分類し、新しい回帰が残っていないこと。テストは`fix:`の変更と合わせるか、独立した`chore:`、文書は`doc:`のコミットにする。

`make -i`などで失敗を無視した終了コードを、テスト成功の根拠にしない。時間がかかる場合は処理が進んでいるかを確認し、想定所要時間に応じて実行時間の上限を調整する。性能計測とビルド・テストを同時に走らせず、処理量と実時間を区別して記録する。

## 任意の拡張候補

以下は調査時の議論を残すための記載であり、plan6の必須ステップと完了条件には含めない。採用する場合は、目的、API、段階ごとの成果物、テストを計画に追加してから実装する。

### クリック・ドラッグ・キャンセルを扱う共通部品

[mouse_policy](../../../examples/boxrig_term/common/mouse_policy.h)と[link_gesture](../../../examples/boxrig_term/common/link_gesture.h)はサンプルの部品であり、公開SDKの選択操作APIではない。共通化する場合は、ドラッグの判定と選択状態の管理を、リンク起動やOSのクリップボード処理から分離する。

部品が扱う候補は、押下位置、選択形状、移動距離によるドラッグ開始、更新中の状態、明示的なキャンセル、解除後のボタン解放までの抑制である。リンクはクリックとして完了した時点で起動を要求し、ドラッグへ移った場合は元の押下位置から選択を始める。修飾キー、複数クリック、子プログラムのマウス報告との優先順位はホストが選べるようにする。

画面外のポインターは、ホストへスクロール要求と次の処理時刻を返す方式を検討する。ホストが表示領域を動かした後、新しいヒット結果で選択を更新する。画面端への補正、スクロール方向・速度・上限、フォーカス喪失、マウス捕捉の喪失を同じ状態管理で扱う。現在のアニメーション実行基盤とホストのイベントループを確認し、新しい常駐スレッドや無条件のポーリングは追加しない。

ESCによる解除では、選択の解除とドラッグの終了を一緒に扱う。解除した押下系列のリピートやキー解放が接続先へ漏れないことを、[入力ルーターの契約](../../../include/boxrig/ui/input.h)に合わせる。キールーターはIMEより前に呼ばれるため、変換中のESCをどちらが扱うかはホストの判断を受ける。選択がない場合のESCの扱いも設定として分ける。

コピーは非空の選択を確定した時点でホストへ要求し、既存のクリップボードを解除操作で消さない。APIは選択状態の問い合わせとキャンセルを提供し、URIを開く処理やOSのクリップボード所有権を内部で引き受けない。通常選択と矩形選択に同じ状態遷移を適用する。

### 元の前景色と背景色を使う反転表示

選択スタイルに、元の前景色と背景色を交換する方式を加える候補である。固定色の灰色塗りは現在のAPIで可能なため、この候補はセルごとの元の配色を使う場合を対象にする。

採用する際は、端末の反転属性、選択の塗りと文字色、ホストの色補正、透明度、カーソルとの合成順序を公開契約にする。秘匿属性や点滅で隠れている文字を選択によって露出させず、CairoとOpenGLで同じ結果にする。通常選択と矩形選択の両方で検証し、色補正が二重に作用する実装を避ける。

### ステップ3の第1段階: 履歴の物理行を列挙する

### ステップ3の第2段階で採用する文字解析の接続

選択を持つビューへ、任意の物理行を解析するプロバイダーを登録する。プロバイダーは、対象端末、画面、物理行の添字から所有権付きの不変レイアウトを返す。作成中の1行のレイアウトは既存の保持量上限で制限し、次の行へ進む前に解放する。ビューに残す選択本文の範囲は描画資源から独立させる。

プロバイダーの所有者とビューは、小さな参照管理用のハンドルを共有する。所有者が終了すると解決関数とそのコンテキストへの呼び出しを停止し、ビューが先に終了した場合も所有者へ無効なビューを残さない。解析条件の改訂を読み出せるようにし、フォントや文字方向が変わった古い矩形を使わない。

既存のレンダラーライフサイクルには、任意の物理行の解析と解析条件の改訂を取得する操作を追加する。描画先へプロバイダーを接続し、終了時には接続用ハンドルを無効にしてから描画資源を解放する。Pango/Cairo、OpenGL、X11、Win32では、表示行で使う文字解析から同じレイアウトを作る。UI層がPangoやDirectWriteへ直接依存する変更は行わない。
