# フォントと画面配置を設定する

[English](../en/fonts-and-layout.md)

boxrig UIでは、端末に使うフォントと文字サイズを変更し、代替フォントやカラーフォントも指定できます。
文字を大きくすると同じウィンドウに収まる行列数も変わるため、実際のセル寸法を取得してレイアウトへ反映します。
文字の内容と列幅はboxrig coreが保持し、フォントの選択と画面上の配置はUIが担当します。

## フォントと文字サイズを指定する

以下は、作成済みのX11コンポーネントのフォントを16 DIPのmonospaceへ変更する関数です。
コンポーネントの配置とフレーム処理を続けると、新しいサイズで文字を表示できます。
共通の`boxrig_font_specification`で、family、文字サイズ、太さ、字形、行間、代替フォントなどを指定します。

```c
#include <boxrig/x11.h>

boxrig_ui_status set_terminal_font(boxrig_x11_terminal_component *component)
{
    const boxrig_font_family family = {
        .name = "monospace", .name_length = 9,
        .resource_id = BOXRIG_FONT_RESOURCE_NONE
    };
    boxrig_font_specification font = boxrig_font_specification_default();
    font.families = &family;
    font.family_count = 1;
    font.size_dip = 16.0f;
    return boxrig_x11_terminal_component_set_font_specification(component, &font);
}
```

DIPは1/96インチを基準とする単位です。
設定は成功時にコピーされ、失敗時は以前の設定と有効な寸法を維持します。
GTK、Wayland、Win32にも対応するsetterがあります。
画面上の文字が変わるのは、通常の配置とフレーム処理が完了した後です。

## Unicodeと代替フォント

coreはUnicodeの文字とセル幅を保持し、UIの文字描画系が利用可能なフォントへ割り当てます。
受信文字コードがShift_JISでも、フォントへ渡す文字列はUnicodeです。

「①」のように、Unicodeで1列と2列のどちらにも扱える文字を曖昧幅文字と呼びます。
端末生成時の`boxrig_terminal_config.ambiguous_width`で幅を選び、既定値は`BOXRIG_AMBIGUOUS_WIDTH_NARROW`の1列です。
2列に固定する場合は`BOXRIG_AMBIGUOUS_WIDTH_WIDE`、フォント依存なら`BOXRIG_AMBIGUOUS_WIDTH_FONT`を指定してください。
フォント依存では、実際に使うフォントの送り幅から列数を決めます。送り幅は次の文字へ進む距離で、代替フォントと太字・斜体も計測に反映します。
この幅は描画、カーソル、折り返し、選択に共通で使われます。接続先のアプリが想定する幅と合わせて指定します。
分類の根拠は[UnicodeのEast Asian Width](https://www.unicode.org/reports/tr11/tr11-44.html)と[文字データ](https://raw.githubusercontent.com/unicode-org/unicodetools/main/unicodetools/data/ucd/17.0.0/EastAsianWidth.txt)を参照してください。

1列／2列指定では、字形を割り当てた列幅に合わせて表示します。フォントを変更しても、本文を保存する列数は変わりません。

フォント依存では、送り幅をセル幅で割り、整数へ切り上げた列数を使います。例えば2.1セル分なら3列を確保し、元の幅の字形を中央に置きます。左右の余白はそれぞれ0.45セル分で、コピーする本文には空白を追加しません。通常の英数字、全角文字、絵文字の列数はこの設定で変わりません。

GTK、X11、Wayland、Win32の端末コンポーネントは、入力を受け取る前にフォント計測を接続します。フォント依存の端末でフォントや倍率を変えると、履歴を含む本文を再計測して配置し直します。端末の接続は維持します。
X11、Win32、OpenGLの描画器を単独で使う場合は、`boxrig_*_renderer_bind_view()`を入力前とフォント変更後に呼びます。描画器の共通ライフサイクルでフレームを準備する場合も、計測が接続されます。コアだけを使う場合は`boxrig_terminal_set_font_width_resolver()`に同期コールバックを登録してください。コールバックは送り幅とセル幅の比を返します。

計測器がない場合や、有効な計測値を得られない場合は1列になります。計測器を外しても既存の本文と列数は保持します。1文字は最大255列で、超過する計測値は`LIMIT_EXCEEDED`になります。画面幅より広い文字は一時的に1列で保持し、再び十分な幅へ広げたときに計測し直します。
フォントから接続先アプリの想定列数は分からないため、必要に応じて1列／2列指定を使ってください。

代替候補はシステム全体、登録済み資源だけ、指定familyだけに制限できます。
フォントファイルとメモリーの登録APIを使うと、アプリが同梱するフォントを指定できます。
ファイルの寿命とメモリーのコピー条件は各登録APIで確認してください。
フォント自体の再配布条件も、そのフォントのライセンスに従います。

## 複雑な文字とカラーフォント

LinuxではPango系、WindowsではDirectWrite系で文字を配置します。
結合文字、双方向の文字、合字は、保存する論理位置と画面上の位置が一致するとは限りません。
コピーや選択には文字配置の対応関係を使います。

OpenType featureや可変フォントの軸を指定できますが、利用可能な機能は描画系とフォントによります。
カラー文字の許可は`boxrig_font_rendering_policy.color_glyphs`で指定します。
許可しただけで、すべての色付きフォント形式を表示できるわけではありません。
実際の能力や不足文字の診断を確認します。

## 行列数と表示寸法

端末の行列数とウィンドウのピクセル寸法を、別々に確定します。
コンポーネントの`get_effective_metrics()`でセル寸法を取得し、実際に割り当てられた領域を`allocate()`へ渡します。
返されたレイアウトと変更要求に従って、coreとPTYをリサイズします。

フォント変更に失敗した場合は、古い有効寸法で表示を続けます。
要求時のフォントサイズから独自に推測した寸法を、成功した値として端末へ反映しないでください。

## DPI・倍率・ズーム

DPIは出力解像度、倍率はUIやコンポジターによる追加の拡大率です。
共通の描画設定は両者を分けて保持します。
Waylandでは配置がsurfaceの論理座標、描画先が物理ピクセルとなります。

コンポーネントのvisual zoomは、入力位置、IME、レイアウトと合わせて変更を進めます。
希望した変更が受理された後も、親のサイズ要求や新しいフレームが未完了の場合があります。
通常のフレーム処理を続け、サイズ要求へ完了を返してください。

## 複数の表示先とサイズ変更

同じモデルへ複数の表示先を接続できます。
ただし端末の行列数と共通の文字寸法には整合が必要で、レイアウトの決定役は一つです。
表示専用の接続から競合する寸法を確定することはできません。

設定が競合した場合は`UNAVAILABLE`などの結果を確認し、モデルを分けるか、同じ有効寸法を使う構成を選びます。
親、モデル、表示先の責任は[基本概念](./architecture.md)と[環境別ガイド](./index.md#アプリケーションに組み込む)を参照してください。
