# 任意文字列の正規表現照合

`boxrig/regex.h`は、端末やGUIを生成せずにUTF-8の文字列を照合するAPIです。
`libboxrig.a`または共有ライブラリ`libboxrig.so`へリンクして使います。
画面の文字列認識器と同じ文法・一致規則で照合できます。

## CLIで試す

次の例は、標準入力から最左最長の一致を探すコマンドです。

```sh
make boxrig-regex
printf 'zaaa' | build/boxrig-regex 'a|aa' 0 1
```

結果の`match 1 3`は、入力のバイト位置1から3の手前までの一致を示します。
`work`は照合に使った処理量です。最後の引数を1にすると、処理を1単位ずつ再開します。
開始バイト位置の既定値は0、1回の処理量の既定値は4096です。
終了値は、一致なら0、不一致なら1、入力やパターンのエラーなら2となります。

NULを含むパターンには`--pattern-file FILE`を使います。
入力中のNULも照合対象です。CLIの容量は、パターンが64KiB、入力が1MiBです。
これらを超えた場合はエラーになります。

## APIで使う

`boxrig_regex_limits_default()`で容量設定を作り、`boxrig_regex_compile()`へパターンとバイト長を渡します。
取得したコンパイル結果は、不変の`boxrig_regex_program`です。
失敗時は`boxrig_text_regex_diagnostic`のコードと`pattern_offset`で原因と位置を確認します。
診断型は画面認識器と共通です。

照合には`boxrig_regex_matcher_create()`を使います。
入力、バイト長、開始バイト位置を指定すると、入力を検証してコピーした照合器を取得できます。
作成時の検証とコピーは、入力長に比例した時間がかかる同期処理です。
不正なUTF-8や開始位置は、返されたエラー位置で確認してください。

`boxrig_regex_matcher_resume()`へ正の処理量を渡すと、照合が進みます。
`IN_PROGRESS`の間は同じ照合器を再開します。
`MATCH`では`start`から`end`の手前までが一致範囲となり、位置は元の入力のバイト単位です。
`NOT_FOUND`では照合が終了しています。終了した照合器は再開できません。

照合器は入力とコンパイル結果を保持するため、作成後は呼び出し側の入力を変更・解放できます。
呼び出し側のプログラム参照も`boxrig_regex_program_destroy()`で解放できます。
複数の所有者でプログラムを保持するときは、`boxrig_regex_program_retain()`を使ってください。
取得した参照ごとに解放が必要です。
同じプログラムの共有操作と参照数の変更は、呼び出し側で直列化してください。
照合器自体は`boxrig_regex_matcher_destroy()`で解放します。

## 文法と一致規則

リテラル、`.`、文字クラス、グループ、`|`、`?`、`*`、`+`、`{m}`、`{m,n}`、`^`、`$`を使えます。
メタ文字のエスケープ、`\n`、`\r`、`\t`、`\u{hex}`も使用可能です。
`\d`、`\s`、`\w`はASCIIの文字クラスです。
空文字と一致する式、後方参照、先読み・後読み、連続した量指定子には対応していません。

文字をUnicodeスカラー単位で照合し、一致全体の両端を拡張書記素境界に限定します。
たとえば`a`と結合アクセントを組み合わせた文字に、`.`だけでは一致しません。
開始位置が書記素の途中なら、次の書記素境界から探します。
UTF-8の継続バイトを開始位置に指定した場合はエラーです。

`^`と`$`は入力全体の先頭・末尾を指します。開始位置を変えても、先頭の意味は変わりません。
`.`は改行にも一致し、正規化や大文字・小文字の変換は行いません。
同じ開始位置に複数の一致がある場合は最長のものを返します。

パターン長、状態数、反復回数、入力長に個別の容量を設定できます。0を無制限の意味では使いません。
固定したパターンでは、不一致の場合も総照合処理量は入力長に比例します。
処理量の1単位は、状態の訪問、遷移、または入力位置の確認です。
文字クラスの訪問では、そのクラスに含まれる範囲を比較します。

## キャプチャを取得する

`(式)`は番号付き、`(?<name>式)`は名前付きのキャプチャです。
番号は開き括弧の順に1から割り当てられ、0は一致全体を表します。
`(?:式)`ではグループ化だけを行い、番号を割り当てません。
名前は`[A-Za-z_][A-Za-z_0-9]*`に従うASCII文字列で、同じ名前は使えません。

一致全体の範囲が同じ場合は、左側の選択肢と貪欲な反復を優先します。
例えば`(a|aa)(a?)`を`aa`に照合すると、グループ1は`a`です。
`(a*)(a*)b`を`aaab`に照合すると、グループ1は`aaa`になります。
空の反復では、同じ入力位置・状態を再訪する経路を打ち切ります。
このため、`(a?)*b`を`aaab`に照合したグループ1は最後の`a`で、`b`だけなら空文字です。
反復されたグループには、最後に参加した値が残ります。
後の反復でグループを通らなかった場合、残るのは以前の参加値です。

`MATCH`後に`boxrig_regex_matcher_result()`を呼ぶと、不変の結果を取得できます。
番号で取得するときは`boxrig_regex_result_get_capture()`、名前では`boxrig_regex_result_get_named_capture()`を使います。
`participated`がfalseなら未参加です。空文字として参加した場合はtrueとなり、`start`と`end`が等しくなります。

キャプチャの位置は、`boxrig_regex_result_data()`が返す一致部分の先頭を0とするUTF-8バイト単位です。
照合器が返す入力全体での位置とは基準が異なります。
キャプチャの両端はUnicodeスカラー境界で、書記素の内部も指定できます。
例えば`a`と結合アクセントからなる文字に`(a)\u{0301}`が一致した場合、グループ1はバイト範囲`[0, 1)`です。

結果は照合器やプログラムを解放した後も読めます。
使い終わった参照ごとに`boxrig_regex_result_destroy()`を呼んでください。
CLIでは、先頭に`--captures`を指定すると番号別の範囲と未参加を表示できます。

```sh
printf 'zb' | build/boxrig-regex --captures '(?<missing>a)?(a*)b' 0 1
```

## 設定保存前に名前を検証する

コンパイル済みのプログラムへ`boxrig_regex_program_find_named_group()`を呼ぶと、名前の存在と番号を取得できます。
入力や照合器、端末を用意する必要はありません。
例えば、テンプレートの`${path}`を設定保存時に検証するには、名前の`path`を渡してください。

```c
bool found;
size_t group;
boxrig_status status = boxrig_regex_program_find_named_group(
    program, "path", &found, &group);
```

名前が定義されていれば、`status`は`BOXRIG_STATUS_OK`、`found`はtrue、`group`は1以上の番号です。
未定義なら`OK`のまま`found`がfalse、`group`が0です。アプリ側では、この結果を使って未定義の参照を拒否してください。
大文字と小文字を区別し、空文字や名前の文法に合わない文字列も未定義として扱います。
引数にNULLがある場合は`INVALID_ARGUMENT`を返し、NULL以外の出力先をfalse・0に戻します。

`(?<path>a)?b`の`path`は、照合で参加しなくても定義済みです。
`{0}`で反復回数を0にしたグループも検索できます。
番号による参照は、0から`boxrig_regex_program_group_count()`までが有効です。番号0は一致全体で、名前を持ちません。
検索ではメモリの確保や再コンパイルを行わず、プログラムの内容や参照数も変更しません。
同じプログラムを共有する場合の直列化は、他のAPIと同様に必要です。

## 画面認識器と共有する

プログラムを共有するには、`boxrig_terminal_register_compiled_text_recognizer()`で登録してください。
認識器はプログラムへの参照を保持するため、登録後に呼び出し側の参照を解放できます。
コンパイル容量はプログラムで確定済みで、登録時には走査・スナップショット・結果の容量を使います。
パターンを渡す既存の登録APIでも、同じキャプチャを利用可能です。

画面の結果は、`boxrig_terminal_text_recognizer_result()`へ認識器ID、`match_id`、`result_set_revision`を渡して取得します。
認識時のキャプチャを返すため、取得時に照合をやり直しません。
本文・レイアウトの変更、結果revisionの更新、認識器の解除後は`STALE`となります。
それ以前に取得済みの結果は、更新や端末の破棄後も有効です。

## キャプチャの容量

`capture_capacity`でグループ数、`capture_byte_capacity`で照合中のキャプチャ保持量を制限できます。
既定値は32グループ・16MiB、最大値は256グループ・256MiBです。
入力が長くなっても照合中のキャプチャ保持量は増えません。容量に収まらない式はコンパイルエラーです。
処理量の1単位には、上限内のグループ情報のコピーも含まれます。

画面認識器の`result_byte_capacity`は、一致部分のバイト列とキャプチャ情報の合計を結果集合ごとに制限します。
既定値は16MiBです。現在の集合と次の走査中の集合が同時に存在するため、最大で2集合分を保持します。
容量を超える場合は不完全を示す通知を返し、途中までの結果は公開しません。
アプリが取得して保持する結果の参照は、この上限に含みません。アプリ側で解放時期と保持数を管理してください。
