# 端末の文字列を取得・選択・検索する

[English](../en/text.md)

端末の表示内容をファイルへ保存したり、文字列を検索したり、特定の出力が現れたことを検出したりできます。
これらの処理はboxrig coreだけでも利用でき、画面を開く必要はありません。
boxrig UIを使うと、マウスによる選択、検索結果の強調、認識結果の装飾も組み合わせられます。

表示内容の保存にはスナップショット、利用者の検索には完全一致検索、出力の検出には監視や認識を使います。
まずは、作成済みの端末から文字列を取り出す例を示します。

## 文字列を取得する

以下は、作成済みの端末からprimary画面と履歴の文字列を取り出す関数です。
アプリケーションで受信データを`boxrig_terminal_feed()`へ渡した後に呼びます。
例えば[READMEのcoreの例](../../README_ja.md#画面を使わずに端末出力を解釈する)の端末なら、赤字指定の制御シーケンスを除いた`Hello`が本文に含まれます。
成功時に返るスナップショットは呼び出し側で所有します。

```c
#include <boxrig/terminal.h>

boxrig_status snapshot_text(boxrig_terminal *terminal,
    boxrig_text_snapshot **snapshot_out)
{
    boxrig_text_snapshot_options options = {
        .screen = BOXRIG_TEXT_SCREEN_PRIMARY,
        .range = NULL,
        .byte_capacity = 1024u * 1024u,
        .line_capacity = 12000
    };
    return boxrig_terminal_create_text_snapshot(terminal, &options, snapshot_out);
}
```

`boxrig_text_snapshot_data()`からUTF-8のバイト列と長さを取得できます。
NUL終端を前提にせず、長さを使って保存してください。
読み終えたら`boxrig_text_snapshot_destroy()`で解放します。
生成後に端末が更新されてもスナップショットの内容は変わりません。

容量を超える場合は`LIMIT_EXCEEDED`となり、途中までの文書を成功として返しません。
画面上のセルだけを一時的に読む`get_cell()`などの借用結果は、端末の次の更新までしか有効ではありません。

## 表示上の行と論理的な行

端末の幅が狭いために折り返した行は、一つの論理行として扱います。
通常の改行は論理行の区切りです。
スナップショットや検索では、折り返しに文字を追加せず、論理行の区切りをLFへ投影します。

位置は画面上の行番号だけでなく、画面の種類、論理行ID、列位置、revisionで表します。
primary画面は履歴を含み、alternate画面は別の文書として扱います。
幅の広い文字や結合文字の途中を、自由な選択境界として扱うことはできません。

## 選択とコピー

UIの表示先には、通常選択と矩形選択のAPIがあります。
`begin_selection()`または`begin_selection_with_options()`で開始し、`update_selection()`で終点を更新します。
文字配置に従ったhit testの結果を使うと、双方向文字でも見た目と操作を対応させられます。

コピーは`boxrig_ui_view_create_selection_snapshot()`で取得します。
矩形選択は表示上の行ごとに投影され、幅広文字は重複させず、行間にはLFを入れます。
選択の見た目を変えても、取得する本文は変わりません。

矩形コピーは既定で、各物理行の表示上の右端まで続く空セルと半角スペース単独（U+0020）を、選択範囲内に限って除去します。
選択範囲の右側に文字があれば、その手前の空白は保持します。
全角空白、NBSP、結合文字を伴うスペースは除去しません。
判定は表示列に従い、残る文字は行内の論理順で出力するため、双方向文字でも文字列の末尾を単純に削る処理とは異なります。

空白を保持する場合は、`boxrig_ui_view_config.rectangular_copy_policy`に`BOXRIG_UI_RECTANGULAR_COPY_PRESERVE_SPACES`を設定します。
既定値は`BOXRIG_UI_RECTANGULAR_COPY_TRIM_TRAILING_SPACES`です。
作成後は`boxrig_ui_view_set_rectangular_copy_policy()`で変更し、`boxrig_ui_view_get_rectangular_copy_policy()`で取得できます。
方針を変えても選択表示と範囲は変わらず、同じ選択から再びコピーできます。通常選択には影響しません。
PRIMARYとCLIPBOARDへのコピーにも、このビュー単位の方針が適用されます。

除去後に空になる行も残し、行間にLFを一つずつ入れます。
例えば、2行目が空なら`abc\n`、3行とも空なら`\n\n`になります。末尾に余分なLFは加えません。
幅が正の選択が空文字列になる場合は成功し、空の本文でコピー先を更新できます。
コピー容量は除去後の本文で検査します。容量超過、メモリ不足、選択の失効では途中の本文を返さず、呼び出し元は既存のクリップボードを保持してください。

矩形の更新で左右の列境界が一致すると、開始点を保持した空の選択になります。
更新は成功し、左右へ動かすと同じ開始点から選択を続けられます。
この状態では行・範囲の問い合わせは0件で、描画する範囲もありません。
コピーは`BOXRIG_UI_UNAVAILABLE`を返します。既存のクリップボードは上書きせずに扱ってください。
`clear_selection()`を呼ぶと、開始点も含めて解除します。

矩形の端点は、論理行IDと物理行の開始位置で保持します。
スクロール後はモデルを同期し、新しいhit testの結果で終点を更新してください。
選択と行スライスの画面内行番号には、`anchor_visual_row_valid`、
`focus_visual_row_valid`、`visual_start_row_valid`、`visual_row_valid`が対応します。
これらが`false`なら対象行は画面外か非表示の画面にあり、行番号の値は0です。
`row_sequence`は、画面外も含めた矩形全体の先頭からの順序を表します。

矩形は、保持中の履歴を含めて画面の高さより長く伸ばせます。
ネイティブの描画部品は、表示時と同じ文字解析をビューへ接続します。
一度も表示していない行でも、全角文字や結合文字を分割せず、双方向文字の表示列を本文へ対応させます。
コピーは矩形全体を対象にし、折り返し行を含む各物理行の間にLFを入れます。描画は現在見える部分だけです。

独自の描画部品では、`boxrig_ui_fragment_layout_provider_create()`で解析部品のハンドルを作り、
`boxrig_ui_view_set_fragment_layout_provider()`へ登録してください。
解析関数は指定された画面・物理行の完全な列対応を所有権付きで返します。
表示位置の変更や描画は不要です。解析中の端末更新、選択操作への再入、ハンドルの破棄は禁止です。
解析条件の改訂を返す関数も登録し、フォントや文字方向を変更したら非ゼロの値を更新してください。
古い条件で作った矩形は`STALE`になり、コピーできなくなります。

解析部品の所有者は、終了時に`boxrig_ui_fragment_layout_provider_destroy()`を呼びます。
ビューは参照を保持しますが、破棄後の解析関数やコンテキストを呼びません。ビューが先に終了しても構いません。
登録の置換や解除は、既存の矩形が無効になる条件です。
初回登録で既存の選択を引き継ぐ場合は、同じ表示方針の解析部品を使ってください。
交換前に表示した文字の位置情報は、次の描画が確定するまで保持します。
ただし、新しい選択には交換後の解析結果を使います。

解析結果は1行ずつ扱い、`maximum_retained_layout_bytes`で1行分の上限も検査します。
選択に残す行数・本文範囲とコピー容量には、それぞれビュー設定の上限が適用されます。
上限超過や解析・確保の失敗では、途中までの結果へ置き換えず、それまでの選択を保持します。
解析部品も表示レイアウトもない画面外の非ASCII行は、`UNAVAILABLE`として更新を拒否します。

履歴のセルを表示位置を動かさずに調べるには、`boxrig_terminal_get_text_fragment_cell()`を使います。
`boxrig_terminal_resolve_text_fragment_cell()`は、幅広文字の継続セルも文字の先頭へ正規化し、文字全体の範囲を返します。
物理行の添字は端末更新で変わり得るため、保存する場合は論理行IDと改訂を照合してください。

選択結果をOSへ渡す処理と、端末内アプリからのOSC 52要求は別です。
後者の許可と完了処理は[ホスト連携](./host-integration.md)を参照してください。

## 完全一致で検索する

coreでは`boxrig_terminal_create_text_search()`で検索を作り、`boxrig_text_search_resume()`へ正の処理量上限を渡して進めます。
UIでは`boxrig_ui_view_begin_search()`と`resume_search()`が検索状態と結果の強調を管理します。

検索文字列はUTF-8のバイト単位で完全一致します。
前方・後方、開始位置、開始位置を越えて一度だけ回り込むかを指定できます。
大文字小文字の無視、Unicode正規化、任意の正規表現検索は、この検索APIには含まれません。

結果は「継続中」「一致」「見つからず」です。
継続中ならイベントループに制御を戻して再開します。
一致後に`reveal_search_result()`で表示位置を動かした場合は、モデルを同期してから描画してください。

## 文字列の出現を監視する

`register_text_monitor()`へ文字列、監視する画面、登録時の既存内容を含めるかを指定します。
`FUTURE_ONLY`は登録後の本文変更で生まれた一致だけを通知します。
表示位置の移動や、本文が同じままの折り返し直しは、新しい出現にはなりません。

`EXISTING_AND_FUTURE`は、登録時の本文を固定したスナップショットから先に調べます。
`dispatch_text_monitors()`へ処理量上限を渡して走査を進めると、既存の一致をprimary、alternateの文書順に、その間に生まれた一致を変更順に公開します。
イベントには既存内容と新しい出現を区別する情報があります。
アプリがイベントをpeekし、処理後にconsumeします。
解析中にアプリのコールバックを呼ぶことはありません。

容量不足で通知を失った場合も、端末の入力と画面更新は続きます。
`text_monitor_needs_rescan()`が真になり、通知キューに空きができると`RESCAN_REQUIRED`が届きます。
アプリは残ったイベントを処理し、`rescan_text_monitor()`を呼んで現在の本文を再走査してください。
成功するまで再走査が必要な状態は残ります。
再走査で取得できるのは現在の一致であり、通知を失った間に現れて消えた文字列は復元できません。

監視の容量は、端末を生成する際の`boxrig_terminal_config`で指定します。

| 対象 | 既定の上限 | 超過時の扱い |
| --- | --- | --- |
| 登録数／登録文字列の合計 | 32件／256 KiB | 登録を拒否し、途中の登録状態を残さない |
| 既存内容のスナップショット | 8 MiB、262,144論理行 | 登録または再走査を拒否し、途中の本文を成功として返さない |
| 初期走査中に保持する新しい出現 | 監視1件あたり1,024件 | 再走査が必要になる |
| アプリへ渡す通知キュー | 端末全体で4,096件 | 再走査が必要になる |
| 1回の本文変更から記録する内容 | 1 MiB、4,096論理行 | 画面更新を続け、再走査が必要になる |

## 認識結果を装飾と操作につなぐ

`register_text_recognizer()`は、URLなどを検出するための範囲を制限した正規表現APIです。
受理する構文は次のとおりです。

| 構文 | 意味 |
| --- | --- |
| UTF-8の文字、`.` | 文字そのもの、任意のUnicodeスカラー値1個 |
| 文字クラス、範囲、否定 | 指定した文字集合との一致 |
| グループ、選択 | 式をまとめる、複数の式から選ぶ |
| `?`、`*`、`+`、`{m}`、`{m,n}` | 繰り返し。有限指定の上端にも上限がある |
| `^`、`$` | 論理行の先頭と末尾 |
| `\n`、`\r`、`\t`、`\\`、`\u{scalar}` | 改行、復帰、タブ、バックスラッシュ、指定したスカラー値 |
| `\d`、`\s`、`\w` | ASCIIの数字、空白、単語の文字 |

空文字にも一致する式、後方参照、先読み・後読み、再帰、ロケール依存の文字クラスは使えません。
Unicode正規化と大文字小文字の同一視も行いません。
登録に失敗した場合は、診断とパターン内のバイト位置を確認してください。

認識は折り返しをつないだ論理行ごとに行い、通常の改行を越えません。
左から最初の一致を選び、同じ開始位置なら最長の一致を使います。
一致同士は重複せず、両端は結合文字を分断しない書記素の境界に限ります。

登録時にはコンパイル、行の長さ、結果数、保持量の上限を指定します。
`boxrig_text_recognizer_limits_default()`の既定値では、1行を1 MiB・1,048,576列まで、1行の一致を4,096件、認識器全体の一致を65,536件まで扱えます。
`resume_text_recognizers()`で処理を分割し、イベントと現在の結果を取得します。
文書サイズの上限は登録後の続行処理で確認します。登録が成功しても、文書が上限を超えていれば`SCOPE_INCOMPLETE`を通知します。
通知された結果はすべて確定済みですが、旧結果を解放する処理が残っている場合があります。`more_work_out`がfalseになるまで続行してください。
作業量上限は実行時間の制限ではありません。メモリー確保や1件のキャプチャ生成などは途中で分割されません。

認識した範囲へUIのtext annotationを設定すれば、色や下線を付けられます。
`RESCAN_REQUIRED`を受けた場合は、その認識器による装飾を消して再走査します。
行の長さや一致数が上限へ達した`SCOPE_INCOMPLETE`は、完全な結果ではありません。
結果の問い合わせで`INCOMPLETE`や`STALE`が返った場合も、以前の結果を現在の本文へ適用しないでください。
クリック時は現在の認識結果を問い合わせてから、アプリが操作を実行します。

完全一致検索、文字列監視、正規表現による認識は別のAPIです。
以前の変換検索の試作を現在の検索機能として使うことはできません。

## 更新後の位置と処理量の扱い

スナップショットは取得時の本文を保持しますが、検索カーソルや範囲は端末の更新の影響を受けます。
`STALE`が返った場合は、以前の位置を現在の本文へそのまま適用しないでください。
再取得、再検索、`rebase_text_range()`による再確認を用途に応じて選びます。

処理量上限は、走査するセルやバイトなどの整数で指定します。
小さい上限で分割し、入力と描画も処理してください。
容量不足、無効な範囲、古い結果を区別すると、長い履歴でもUIを止めずに扱えます。
