# X11アプリケーションへ組み込む

[English](../../en/platforms/x11.md)

boxrig UIのX11コンポーネントを使うと、既存の親ウィンドウ内へ端末の表示領域を作り、キーやマウス、IMEから操作できます。
文字の解釈と端末の状態はcore、描画と入力受付はUIが担当します。
親ウィンドウ、イベントループ、シェルなどとの通信はアプリケーションから接続します。

[READMEの実装例](../../../README_ja.md#アプリケーションへ端末表示を加える)では、固定文字列を表示する短いコードを紹介しています。
ウィンドウ作成から実行する場合は[UI向けstep-by-step](../step-by-step/step-by-step-ui.md)、既存のアプリケーションへ組み込む場合は、このページの生成、イベント、配置の順に進んでください。

## 必要なライブラリ

core、UI、X11のライブラリを使います。
文字描画にはPango/Cairo、ウィンドウとの連携にはX11、Xrender、Xfixes、Xcompositeなどが必要です。
PTYを使う場合はsessionとPOSIXも加えます。
依存とリンク順は[ビルドガイド](../building.md)と[step-by-stepのMakefile](../step-by-step/Makefile)を参照してください。

## 親ウィンドウへ配置する

以下は、端末を表示する子ウィンドウを作る関数の例です。
接続済みの`Display`、作成済みの親`Window`、端末を参照するUIモデルを渡します。
点滅を使うため、同じイベントループで使う[アニメーションruntime](../blinking.md)も用意してください。
ウィンドウ全体を作るコードではなく、アプリケーションから呼ぶ生成部分の抜粋です。

```c
#include <boxrig/x11.h>

boxrig_ui_status create_terminal_child(Display *display, Window parent,
    boxrig_ui_model *model, boxrig_ui_animation_runtime *animations,
    boxrig_x11_terminal_component **component_out)
{
    boxrig_x11_terminal_component_config config =
        boxrig_x11_terminal_component_config_default();
    config.animation_runtime = animations;
    return boxrig_x11_terminal_component_create_child(
        display, parent, model, &config, component_out);
}
```

成功するとコンポーネントが子ウィンドウと表示先を所有します。
親、Display、モデル、端末はアプリケーションの所有です。
配置寸法を渡し、表示を有効にしてから描画を進めます。

すでにある描画先を使う`create_on_target()`もあります。
この場合は描画先と入力先のイベント選択、表示、移動、破棄をアプリケーションが担当します。
互換性のあるVisual、depth、Colormapが必要です。
初回の実装には、責任範囲が小さい子ウィンドウ方式を使うと追いやすくなります。

## イベントと描画を進める

Xイベントを`boxrig_x11_terminal_component_dispatch_event()`へ渡します。
コンポーネントに関係しないイベントは、親や他の部品で処理します。
`BLOCKED`は入力を破棄してよいという意味ではありません。
送信側の空きを作った後、同じイベントを再試行します。
ただし、入力を保留したときの`get_input_state()`の世代と現在の世代が異なる場合は、再試行せず破棄します。

通信を進めたら、モデルを同期し、`boxrig_x11_terminal_component_frame()`を呼びます。
`additional_dispatch`が真なら待機前にもう一度処理します。
`frame_pending`だけが真の場合は、次のイベントを待つ必要がある場合もあります。
常時描画を繰り返すループにはしません。

IME、クリップボード、点滅を含む待機の例は、[X11のイベントループ](../../../examples/boxrig_term/x11/event_loop.c)にあります。
固定文字列だけを表示するstep-by-stepの最初の例では、待機の説明を小さくするため点滅を無効にしています。

## ユーザー入力を一時的に禁止する

一時的な入力禁止には`boxrig_x11_terminal_component_set_input_enabled(component, false)`を使ってください。
対象コンポーネントの保留キー・IME・受信clipboard・pasteを取り消します。
選択・コピー・履歴移動・描画、アプリケーションの入力router、端末の問い合わせ応答は引き続き利用できます。
すでにcoreへ投入したデータと、同じ端末を使う別コンポーネントの入力は保持します。

開始済みpasteの終端に送信容量が必要な間は、要求を受け付けて`BUSY`を返し、状態が`STOPPING`になります。
出力を消費した後も通常の`frame()`を続け、`get_input_state()`で`DISABLED`を確認してください。
この完了条件は終端をcoreへ投入したことで、通信先へ届いたことではありません。
`true`による再開は`STOPPING`中には受け付けず、入力dispatch内からの要求も状態を変えず`BUSY`を返します。
再開後も、禁止前の遅延応答と、キーを離すまでの押下系列は端末へ送信しません。

## 配置とサイズを変更する

親の利用可能領域が決まったら`boxrig_ui_component_allocation`へ位置、幅、高さ、ウィンドウ状態を設定し、`allocate()`へ渡します。
返されたレイアウトから有効な行列数が分かります。

モデルに対するレイアウトの決定役は一つです。
行列数の変更要求を取り出し、[セッション](../sessions.md)またはcoreへ適用してから`complete_grid_resize()`で成否を返します。
フォント変更やズームによる親のサイズ要求も、ホストで適用して完了させます。
要求した寸法とOSで確定した寸法を混同しないでください。

## 別の親ウィンドウへ移す

`boxrig_x11_terminal_component_reparent(component, parent)`で、所有する子ウィンドウを別の親へ移せます。
標準描画とOpenGLの両方で、同じ子Window、view、選択、表示設定、端末と通信セッションを保持します。
親は同じDisplay・screen上の有効なInputOutputウィンドウにしてください。
自身や子孫、借用先を使う`create_on_target()`は移設の対象外です。

キーやマウスの押下中、IMEの未確定入力中、貼り付け中、描画や入力のコールバック中は`BUSY`を返します。
処理を終えた後、イベントループから再試行してください。
アプリが保留した入力は、`get_input_state()`の世代が変わった時点で破棄します。
コピー済みのクリップボードと送信中の選択データは、同じ子Windowで保持します。

`OK`なら親変更が反映されており、旧親を破棄できます。
この時点では画面への提示完了まで保証しません。
失敗した場合は旧親と入力接続を保持します。
新しい親は、次の移設かコンポーネントの破棄まで生存させてください。
親変更と入力コンテキストの条件は、[Xlibの仕様](https://www.x.org/releases/X11R7.6/doc/libX11/specs/libX11/libX11.html)に従います。

移設だけでは配置や端末の行列数を変えません。
移動先の領域を`allocate()`へ渡し、レイアウト要求を完了させます。
入力を受け付ける場合は`request_focus()`も呼んでください。
[往復移設の例](../../../examples/x11/transfer.c)はF6で移動します。
`make build/examples/x11_transfer`で標準版、`make build/examples/x11_transfer_opengl`でOpenGL版を生成できます。

## OpenGLを選ぶ

標準構成はソフトウェア描画です。
OpenGLの子ウィンドウには[専用の生成API](../../../include/boxrig/x11/opengl_component.h)と`boxrig-x11-ogl`のSDKを使います。
GLX/EGLの選択と描画方式の条件は[描画方式](../renderers.md)を参照してください。

生成APIが失敗したとき、別方式へ切り替えるかどうかはアプリケーションが決めます。
新しいコンポーネントを生成する場合も、既存の端末とモデルを維持できます。

## 解放と実行例

入力の受付と待機への登録を止め、コンポーネント、モデル、端末の順で解放します。
Displayと親ウィンドウは、コンポーネントの破棄が終わるまで有効にしてください。

全体例は[step-by-step](../step-by-step/step-by-step-ui.md)、PTYや設定を含む例は[boxrig_term](../boxrig_term.md)です。
全操作の条件は[コンポーネントの公開ヘッダー](../../../include/boxrig/x11/component.h)で確認できます。
